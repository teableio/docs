### Percorso

POST /api/table/\{tableId\}/record

### Richiesta

#### Parametri del percorso

* tableId (string): identificatore univoco della Tabella.

#### Corpo della richiesta

* **records (obbligatorio)**
  * Descrizione: array di Record da creare
  * Tipo: Array
  * Esempio:
    ```json
    [
      {
        "fields": {
          "Name": "John Doe",
          "Age": 30,
          "Email": "john@example.com"
        }
      },
      {
        "fields": {
          "Name": "Jane Smith",
          "Age": 28,
          "Email": "jane@example.com"
        }
      }
    ]
    ```
  * Nota: ogni Record è un elemento contenente un oggetto `fields`. L'oggetto `fields` contiene i nomi dei Campi e i relativi valori. Ogni tipo di Campo ha una struttura di valori diversa; per i dettagli, consulta [Tipi di valore dei Campi dei Record](/it/api-doc/record/interface).
  * Valori predefiniti: per i Campi omessi da `fields` viene utilizzato il valore predefinito della Tabella, se configurato. Se un Campo obbligatorio non ha un valore predefinito oppure se passi esplicitamente `null` a un Campo obbligatorio, la richiesta non riesce.
* **fieldKeyType (facoltativo)**
  * Descrizione: specifica il tipo di chiave del Campo
  * Tipo: String
  * Valori possibili:
    * "name": usa il nome del Campo come chiave
    * "id": usa l'ID del Campo come chiave
    * "dbFieldName": usa il dbFieldName del Campo come chiave
  * Esempio: `"name"` oppure `"id"` oppure `"dbFieldName"`
  * Nota: se non specificato, per impostazione predefinita viene utilizzato il nome del Campo come chiave.
  * Utilizzo:
    * Quando è impostato su "name":
      ```json
      {
        "fields": {
          "Name": "John Doe",
          "Age": 30
        }
      }
      ```
    * Quando è impostato su "id":
      ```json
      {
        "fields": {
          "fldABCDEFGHIJKLMN": "John Doe",
          "fldOPQRSTUVWXYZ12": 30
        }
      }
      ```
* **typecast (facoltativo)**
  * Descrizione: indica se convertire automaticamente i tipi dei valori dei Campi. Per impostazione predefinita viene applicata una convalida rigorosa, che richiede la corrispondenza tra i valori di input e il tipo di dati del Campo corrente. Se abilitato, il sistema tenterà la conversione automatica.
  * Tipo: Boolean
  * Valori possibili: true o false
  * Esempio: `true`
  * Nota: se impostato su true, il sistema tenterà di convertire i valori di input nel tipo di valore corretto per il Campo.
  * Esempi di utilizzo:
    * Campo di collegamento: consente di utilizzare direttamente il testo della chiave primaria per creare il collegamento
      ```json
      {
        "User table": "John Smith"
      }
      ```
    * Campo data: consente di utilizzare stringhe di data in formato non standard
      ```json
      {
        "Date": "2023-05-15"
      }
      ```
    * Campo utente: consente di utilizzare direttamente il nome utente
      ```json
      {
        "Assigned To": "John Doe"
      }
      ```
* **order (facoltativo)**
  * Descrizione: specifica la posizione dei nuovi Record in una determinata Vista
  * Tipo: Object
  * Proprietà:
    * viewId
      * Descrizione: ID della Vista [(come ottenerlo)](/it/api-doc/get-id#viewid)
      * Tipo: String
      * Esempio: `"viwABCDEFGHIJKLMN"`
    * anchorId
      * Descrizione: ID del Record di ancoraggio [(come ottenerlo)](/it/api-doc/get-id#recordid)
      * Tipo: String
      * Esempio: `"rec123456789ABCDE"`
    * position
      * Descrizione: posizione relativa al Record di ancoraggio
      * Tipo: String
      * Valori possibili:
        * "before": prima del Record di ancoraggio
        * "after": dopo il Record di ancoraggio
      * Esempio: `"after"`
  * Esempio completo:
    ```json
    {
      "viewId": "viwABCDEFGHIJKLMN",
      "anchorId": "rec123456789ABCDE",
      "position": "after"
    }
    ```
  * Nota: l'uso di order consente di controllare con precisione la posizione dei nuovi Record in una determinata Vista.

### Risposta

#### Risposta in caso di successo

* Codice di stato: 201 Created
* Corpo della risposta: restituisce i dati dei Record creati.

**Esempio di corpo della risposta**

```json
{
  "records": [
    {
      "id": "record789",
      "fields": {
        "single line text": "text value 1"
      }
    },
    {
      "id": "record567",
      "fields": {
        "single line text": "text value 2"
      }
    }
  ]
}
```

### Risposte di errore

* Codice di stato: 400 Bad Request: formato del corpo della richiesta non valido o Campi obbligatori mancanti.
* Codice di stato: 404 Not Found: il tableId specificato non esiste.

## Creare o aggiornare record tramite un campo univoco {#upsert-by-unique-field}

Quando sincronizzi dati esterni, puoi trovare i record tramite un valore univoco, come un numero d’ordine o un codice cliente, senza cercare prima gli ID dei record.

```text
POST /api/table/{tableId}/record/upsert
```

<Info>Questo endpoint richiede una tabella con il motore v2 e non è disponibile tramite viste condivise. La modalità `error` richiede il permesso di creare record; `ignore` e `update` richiedono i permessi di creazione e aggiornamento.</Info>

### Corpo della richiesta

| Parametro | Descrizione |
| --- | --- |
| `matchField` | Obbligatorio. ID del campo di corrispondenza, per il quale deve essere attivo un vincolo di univocità. È supportato un solo campo, senza chiavi composite. |
| `onConflict` | Obbligatorio. Come gestire una corrispondenza esistente; vedi la tabella seguente. |
| `records` | Obbligatorio. Almeno un record. Ogni record fornisce i valori in `fields` e deve includere un valore di corrispondenza non vuoto. I valori di corrispondenza non possono ripetersi nella stessa richiesta. |
| `fieldKeyType` | Facoltativo. Tipo di chiave in `fields`, come nell’endpoint di creazione. `matchField` contiene sempre un ID di campo. |
| `typecast` | Facoltativo. Indica se tentare la conversione automatica dei tipi dei valori, come nell’endpoint di creazione. |

I record senza corrispondenza vengono creati. In caso di corrispondenza, si applica `onConflict`:

| Valore | Comportamento |
| --- | --- |
| `error` | L’intera richiesta fallisce se uno dei valori di corrispondenza esiste già. |
| `ignore` | Conserva il record esistente e ignora quel record in ingresso. |
| `update` | Aggiorna solo i campi forniti; gli altri mantengono il loro valore. |

Ad esempio, se `fldOrderNumber` è un campo numero d’ordine con un vincolo di univocità, questa richiesta crea un ordine o aggiorna lo stato di uno esistente:

```json
{
  "fieldKeyType": "id",
  "matchField": "fldOrderNumber",
  "onConflict": "update",
  "records": [
    {
      "fields": {
        "fldOrderNumber": "ORDER-001",
        "fldStatus": "Pagato"
      }
    }
  ]
}
```

### Risposta

In una risposta riuscita, `results` segue l’ordine di ingresso e `index` parte da 0. `summary` conta i record richiesti e ciascun tipo di risultato.

| `status` | Significato |
| --- | --- |
| `created` | È stato creato un nuovo record. |
| `updated` | È stato aggiornato un record esistente. |
| `unchanged` | I valori esistenti corrispondono già o non ci sono campi da aggiornare. |
| `skipped` | Un record esistente è stato ignorato in modalità `ignore`. |

I risultati includono `recordId` e `record` solo se il chiamante può leggere il record. Il contenuto dei campi resta soggetto ai permessi di lettura.

```json
{
  "results": [
    {
      "index": 0,
      "status": "updated",
      "recordId": "recExample",
      "record": {
        "id": "recExample",
        "fields": {
          "fldOrderNumber": "ORDER-001",
          "fldStatus": "Pagato"
        }
      }
    }
  ],
  "summary": {
    "requested": 1,
    "created": 0,
    "updated": 1,
    "unchanged": 0,
    "skipped": 0
  }
}
```
