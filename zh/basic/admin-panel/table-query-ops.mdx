---

<Tip>私有化部署商业版及以上适用</Tip>

路径：管理面板 → 表格查询运维

当大表中的视图、筛选、关联或搜索变慢时，可以使用 **表格查询运维**。后台分析器会持续观测查询负载，并把观测结果整理成推荐。页面会列出这些推荐，实例管理员可以查看依据、对具体的表做深度分析，并确认需要执行的数据库变更。

列表上方的计数概括了当前情况：观测窗口、请求数、慢查询、超时、待处理和已接受的推荐、执行中和失败的任务，以及有多少张表的搜索索引已就绪或已降级。

## 查看推荐

页面默认打开 **推荐** 标签，并按优先级排序。分析器会同时衡量查询风险和表的使用热度，最值得处理的排在最前面。

搜索表、Base 或 Space 的 ID 可以在全部推荐中过滤；其他文本只在当前结果内过滤。状态和风险筛选器可以进一步缩小范围。

每条推荐都会标出所属的空间、Base 和表名。展开某一行，可以看到推荐依据、系统决策和 SQL 诊断信息：

| 板块 | 说明 |
| --- | --- |
| **触发来源** | 推荐从哪里来：实际查询观测、保存的视图配置，或关联字段配置。来自保存的视图配置说明还没观测到慢查询，是配置本身有风险。 |
| **访问路径** | 这张表被顺序扫描和索引扫描命中的次数对比。 |
| **原因** | 可读的成因，例如表数据量大、筛选或排序字段上没有可用索引、排序开销高、已观测到超时等。 |
| **查询结构** | 具体在筛选和排序哪些字段，以及各自使用的匹配方式。 |
| **建议索引** | 推荐准备建索引的字段，以及给出的理由。 |

点击 **深度分析** 会打开分析工作台，并自动填入该表。

当分析器观测到某张表存在大量子串搜索时，会针对整张表给出一条 **generated-text GIN** 推荐，而不是逐个字段建索引。这类推荐行会用 **创建搜索路径** 取代 **深度分析**，也不会出现 **添加索引**：搜索访问路径要在分析工作台里应用，并且需要先做一次 **EXPLAIN 样例搜索**。该表建好搜索路径后，这条推荐会自动关闭。

旁边还有两个标签：

| 标签 | 展示内容 |
| --- | --- |
| **热点表** | 最繁忙的表，包含请求数、慢查询、超时和最长查询耗时。 |
| **任务** | Teable 创建的修复任务，包含状态、尝试次数、执行 worker 和最后一次错误。 |

当配置问题拖住整个流程时，列表上方会出现提示横幅：已配置搜索访问路径但运行时开关未开启；部分表的访问路径处于 stale 或待重建状态，这些表的搜索已静默退回更慢的 `ILIKE` 扫描；或者最老的排队任务等待过久，说明可能没有 worker 在消费。先处理横幅中提示的问题，再去处理下方的推荐。

### 读懂决策徽章

每条推荐都会带上系统对它的最新决策：

| 徽章 | 含义 |
| --- | --- |
| **需人工确认** | 只能由管理员确认执行。 |
| **影子 · 可自动** | 推荐已满足自动执行条件，但自动执行未开启，因此没有做任何变更。 |
| **自动执行中** / **已自动执行** | 自动执行已接受该推荐并完成变更。 |
| **验收失败 · 退避中** | 自动变更没有通过验收，Teable 会等待更久再重试该表。 |
| **冷却中** | 同一范围刚刚变更过，系统暂时不会再动它。 |
| **暂不执行** / **自动执行未生效** | 计划依据或表的规模没有达到自动执行的标准。 |

<Info>默认情况下，Teable 只记录决策并生成推荐和任务记录，不会自动改动数据库。自动执行需要通过 `V2_TABLE_QUERY_OPS_AUTO_ACCEPT=auto` 主动开启，且只对执行计划显示明显成本改善的小表生效，其余都会等待管理员确认。</Info>

### 按建议添加索引

如果认可某条推荐给出的索引，点击该行的 **添加索引**。确认后 Teable 会接受这条推荐，并在底层 PostgreSQL 表执行 `CREATE INDEX CONCURRENTLY`；执行计划未验证时，仍会按推荐字段建索引。弹窗里会再列一遍推荐依据，方便最后核对。

预估行数达到 50,000 行及以上的表，需要先在弹窗中勾选确认已安排维护窗口，确认按钮才可用。大表的并发建索引耗时较长，执行期间会额外增加负载。

执行后 Teable 会提示 **索引已创建** 或 **已接受推荐并写入任务**；属于后者时，到 **任务** 标签跟进执行结果。如果这条推荐没有可执行的物理列，**添加索引** 会保持不可用并说明原因，此时改用分析工作台进一步排查。

## 发起深度分析

点击 **分析工作台** 可以主动分析指定范围，例如用户反馈某张表很慢，但还没有对应的推荐时。

| 分析类型 | 适用场景 |
| --- | --- |
| **查询与索引** | 查找查询风险和可能的索引优化建议。 |
| **子串搜索** | 判断子串搜索访问路径能否在保持匹配行为不变的情况下加快包含搜索。 |

选择 **表**、**Base** 或 **Space**，填写对应 ID，再选择分析类型。如果已经知道哪张表较慢，建议从 **表** 开始分析。

点击 **生成查询报告** 或 **生成搜索报告**。报告会汇总发现的风险和建议的后续操作。生成搜索报告时，**EXPLAIN 样例搜索词** 为可选项。填写后，报告会检查建议的子串搜索访问路径是否保持相同的查询结果，并比较执行计划和多次查询耗时。Teable 不会保存这个搜索词。

<Info>查询报告不会修改数据库。执行子串搜索建议前，必须填写 **EXPLAIN 样例搜索词** 并由管理员确认。</Info>

对于大表，请先评估影响，并把需要确认执行的变更安排在合适的维护窗口。
