Los campos Fórmula calculan resultados a partir de otros campos del mismo registro. Pueden realizar operaciones matemáticas, unir texto, calcular fechas y aplicar lógica condicional. Úsalos para convertir reglas de cálculo repetitivas en campos.

## Casos de uso

| Escenario | Ideal para |
| --- | --- |
| Cálculo automático | Calcular el precio total, el beneficio o la puntuación a partir de la cantidad, el precio unitario, el descuento y otros campos |
| Procesamiento de texto | Unir texto, extraer contenido o analizar información mediante un delimitador |
| Procesamiento de fechas | Calcular diferencias entre fechas, comprobar intervalos de tiempo o generar fechas futuras |
| Lógica condicional | Devolver resultados distintos según ciertas condiciones, como estados, indicaciones o categorías |

## Conceptos básicos de las fórmulas

### Tipos de datos

Antes de escribir una fórmula, confirma los tipos de los campos utilizados en el cálculo. Los distintos tipos admiten operaciones y funciones diferentes.

| Tipo | Descripción | Usos habituales |
| --- | --- | --- |
| Número | Enteros o decimales | Aritmética, acumulaciones, comparaciones |
| Texto | Valores de cadena | Unir, extraer, reemplazar, dividir |
| Fecha | Valores de fecha o fecha y hora | Calcular intervalos, comparar fechas |
| Booleano | `TRUE` o `FALSE` | Condiciones y operaciones lógicas |

### Hacer referencia a campos

En una fórmula, haz referencia a otro campo mediante su nombre. Escribe el nombre del campo entre `{}` y asegúrate de que coincida con el nombre real del campo:

```js
{Precio unitario} * {Cantidad}
```

### Operadores

| Operador | Uso |
| --- | --- |
| `+` | Calcula la suma de números o une cadenas |
| `-` | Calcula la diferencia entre números |
| `*` | Calcula el producto de números |
| `/` | Calcula el cociente de números |
| `%` | Calcula el resto |

## Funciones y expresiones

### Funciones habituales

Las funciones realizan operaciones específicas. Por ejemplo, `SUM` calcula un total, `LEFT` extrae caracteres del principio de un texto, `TEXTBEFORE` extrae el texto anterior a un delimitador y `TEXTSPLIT` divide el texto mediante un delimitador.

Consulta la [hoja de referencia de fórmulas](/es/basic/field/formula/cheat-sheet) para conocer más funciones.

### Procesamiento de texto

| Operación | Ejemplos de funciones | Descripción |
| --- | --- | --- |
| Unir texto | `&`, `CONCATENATE` | Une dos o más valores de texto |
| Extraer texto | `LEFT`, `RIGHT`, `MID`, `TEXTBEFORE` | Extrae parte de una cadena |
| Dividir texto | `TEXTSPLIT` | Divide el texto en varios valores mediante un delimitador |

### Condiciones lógicas

Usa la función `IF` para devolver valores diferentes según una condición:

```js
IF(condición, valor_si_verdadero, valor_si_falso)
```

Para comprobar si un campo está vacío, compáralo con `BLANK()`. Por ejemplo, `IF({Peso}=BLANK(), 1, 2)` devuelve `1` cuando un campo numérico está vacío y `2` en caso contrario.

### Expresiones complejas

Una fórmula compleja puede incluir varias funciones, referencias a campos y operadores. Usa paréntesis para controlar el orden de cálculo:

```js
({Precio unitario} * {Cantidad}) * (1 - {Descuento})
```

## Visualización y mantenimiento de resultados

### Formato y visualización interactiva

Los resultados de las fórmulas también pueden usar opciones de [formato](/es/basic/field/common/formatter) y [visualización interactiva](/es/basic/field/common/show-as), como porcentaje, barra de progreso o estilos de iconos. Las opciones disponibles dependen del tipo de resultado de la fórmula.

### Depuración y optimización

- **Comprueba los tipos de datos**: Confirma que las operaciones y funciones utilicen los tipos de datos correctos.
- **Verifica las referencias a campos**: Confirma que los nombres de los campos estén escritos correctamente.
- **Prueba paso a paso**: Divide las fórmulas complejas en partes más pequeñas y pruébalas por separado.
- **Evita cálculos repetidos**: Si el mismo cálculo se utiliza en varios lugares, considera almacenar el resultado en un campo independiente.

### Actualización programada

Las fórmulas suelen recalcularse cuando cambian los campos a los que hacen referencia. Una fórmula que usa `TODAY()`, `NOW()`, `FROMNOW()` o `TONOW()` también cambia con el tiempo, por ejemplo «días hasta el vencimiento»: aunque el registro no cambie, el resultado debería actualizarse al día siguiente.

En estos campos, haz clic en **Actualizar ahora** en el menú del encabezado de columna para recalcular al instante toda la columna con la hora actual. Para que se mantenga al día automáticamente, activa **Actualización automática programada** en la configuración del campo (Business o superior):

<img
  src="/images/docs/base/2026-11-24-field-periodic-refresh.png"
  alt="Área de actualización programada al final de la configuración de un campo de fórmula, con la actualización automática activada y frecuencia diaria"
  className="docs-screenshot"
/>

- Una fórmula que solo usa `TODAY()` se actualiza una vez al día; el cambio de fecha se determina con la zona horaria que se muestra en la configuración.
- Una fórmula que usa `NOW()`, `FROMNOW()` o `TONOW()` se actualiza aproximadamente cada 15 minutos y recalcula todos los registros de la tabla cada vez. En tablas grandes puede consumir muchos recursos; si basta con precisión de días, usa `TODAY()`.

La actualización automática solo se ejecuta mientras la base se usa con regularidad; una base sin uso durante un tiempo se pone al día la próxima vez que alguien abre una tabla. **Última actualización** en la configuración del campo indica cuándo se ejecutó la más reciente. Si se baja de plan, la actualización automática se pausa y conserva su configuración, y se reanuda al pasar a Business o superior; **Actualizar ahora** no se ve afectado.

Los campos de [búsqueda](/es/basic/field/lookup), [acumulación](/es/basic/field/rollup), [búsqueda condicional](/es/basic/field/conditional-lookup) y [acumulación condicional](/es/basic/field/conditional-rollup) cuyo filtro usa una fecha relativa como **hoy**, **semana actual** o **número pasado de días** también se pueden actualizar al momento o de forma programada. Se actualizan a diario, semanalmente o mensualmente, según el periodo más corto del filtro.

### Límites de complejidad

Al guardar una fórmula, Teable la expande primero a la estructura que participa realmente en el cálculo y luego comprueba el tamaño de esa estructura. Si supera un límite, el guardado se rechaza y el mensaje indica qué se ha excedido y cuál es el límite aplicable —el número de nodos expandidos, la profundidad de anidamiento del cálculo, la profundidad de las referencias entre fórmulas— y el cambio no se guarda.

Una fórmula corta también puede excederse: si una fórmula referencia a otra y esa a una tercera, la estructura expandida crece deprisa. Guardar los resultados intermedios en campos propios y reducir las referencias repetidas y las ramas complejas suele bastar para volver por debajo del límite.

Si una fórmula guardada alcanza un límite durante el cálculo, el campo indica `La compilación de la fórmula supera el límite de cálculo; los resultados no se actualizaron` en la [actividad de los Campos calculados](/es/basic/view/grid). Una vez simplificada la fórmula, la siguiente escritura vuelve a calcular el campo.
