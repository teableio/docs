## السماح لوكيل ذكاء اصطناعي بتنفيذ النشر

صُمم مستودع النشر ليستخدمه وكلاء الذكاء الاصطناعي. وجّه
بيئة وكيلك (Claude Code أو Codex أو غيرهما) إلى
[teableio/teable-deployment](https://github.com/teableio/teable-deployment)،
وأخبره بالبيئة التي تنشر إليها، وسيتمكن من تنفيذ النشر
من البداية إلى النهاية. جهّز ثلاثة أمور:

1. **نطاق** — تُشتق جميع العناوين من نطاق أساسي واحد، مثل
   `teable.example.com`.
2. **رمز DNS** — رمز API للمنصة التي تستضيف DNS
   (مثل Cloudflare أو Route 53)، حتى يمكن إعداد سجلات DNS وشهادات TLS
   تلقائيًا. احصر نطاق صلاحيته في تلك المنطقة وحدها.
3. **إمكانية الوصول إلى هدف النشر:**

| الهدف | ما يجب تقديمه للوكيل |
|---|---|
| جهازك — Docker متكامل، وضع `local` | يكفي وجود Docker على الجهاز؛ لا يلزم نطاق أو رمز DNS (يعمل كل شيء على `*.localhost`) |
| خادم سحابي — Docker متكامل | وصول SSH إلى الجهاز |
| مجموعة مُدارة على AWS (EKS) / GCP (GKE) / Azure (AKS) | أنشئ المجموعة، ثم قدّم ملف `kubeconfig` الخاص بها |
| أي مجموعة Kubernetes موجودة | ملف `kubeconfig` يمكنه تثبيت إصدارات Helm |

هذا كل ما يلزم؛ تتولى أدلة المستودع ونصوص الفحص وبيانات الإصدارات
إرشاد الوكيل خلال بقية العملية.
