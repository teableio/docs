<Tip>セルフホストのBusinessプラン以上で利用できます</Tip>

パス：システム管理 → 暗号鍵の収束

サーバーシークレットを変更または削除しても、データベースにすでにあるデータは、古いシークレットで暗号化されたままです。このページでは、シークレットの設定を確認し、そのデータを現在のキーによる暗号化へ移します。その後であれば、古いシークレットを削除できます。手順全体の順序については、[シークレットの収束](/ja/deploy/secret-convergence)をご覧ください。

このページには、保存済みの暗号文、個人アクセストークン、サーバーシークレットの3つのタブがあります。

## サーバーシークレット {#server-secrets}

読み取り専用です。環境変数を確認するためのもので、シークレットの値が表示されることはありません。

`SECRET_KEY`、`SANDBOX_JWT_SECRET`と、専用の変数または`_OLD`変数がまだ設定されている各シークレットが一覧表示されます。一覧にないシークレットは`SECRET_KEY`に従っており、専用の変数は不要です。

| 列 | 意味 |
|---|---|
| 変数 | 環境変数とその用途です。**廃止予定**のラベルが付いた変数は、既存のデータを読み取るためだけに残されています。**このデプロイでは読み込まない**は、変数が設定されているものの、このエディションまたは設定では使われないことを示します |
| 値の取得元 | 値が変数そのものから来ているのか、`SECRET_KEY`にフォールバックしているのか、`SECRET_KEY`から派生しているのか、以前の公開デフォルト値なのかを示します。その後ろに、値のフィンガープリントが続きます。**公開値**は、誰でも計算できる値であることを示します |
| `_OLD` | 設定されている`_OLD`変数と、それぞれのフィンガープリントです。`_OLD`は、既存データの検証または復号にのみ使われます |
| SECRET_KEY のみの場合と同じ | **同じ**は、専用変数を削除しても値が変わらないことを示します。**異なる**は、値が変わるため、先に古い値を残しておく必要があることを示します |

フィンガープリントは、値のSHA-256の16進数表記の先頭8文字です。シークレットストアにある記録と照合するために使います。

ページの上部には、まだ設定されている専用変数と`_OLD`変数の数、およびそのうち公開されている値の数がまとめて表示されます。`SECRET_KEY`が未設定の場合や、公開されているデフォルト値のままの場合は、その旨が別に表示されます。

## 保存済みの暗号文 {#stored-ciphertexts}

データベース内の暗号文を、現在のキーで再暗号化します。対象は、データベーステナントの接続文字列、アプリの環境変数、AI設定、サードパーティ認証情報です。有効になっているオートメーションが実行に使うステップのコピーは書き換えません。[それぞれの古い値を残す期間](/ja/deploy/secret-convergence#old-value-retention)をご覧ください。

1. **Dry-run**（ドライラン）をクリックします。件数を数えるだけで、何も変更しません。
2. 結果を確認してから、**再暗号化**をクリックします。
3. もう一度ドライランを実行し、**再暗号化が必要**と**復号不可**の両方が0であることを確認します。

| 列 | 意味 |
|---|---|
| 合計 | このテーブルで、暗号化されているかどうかにかかわらず、シークレット値を保持している行の数です |
| 最新 | すでに現在のキーで暗号化されています。何もする必要はありません |
| 再暗号化が必要 / 再暗号化済み | ドライランでは書き換え対象となる行、実際の実行では書き換えた行です |
| 競合 | 書き換え中に別のリクエストによって行が変更されたため、今回はスキップされました。もう一度実行してください |
| 復号不可 | 現在のキーでも、設定済みのどの`_OLD`でも行を開けないため、そのまま残されます。結果には、これらの行のIDが、テーブルごとに最大50件まで表示されます |

データのないテーブルは、デフォルトで折りたたまれています。

<Warning>
実行する前に：データベースと環境変数（すべての`_OLD`変数を含む）をバックアップし、各アプリインスタンス（すべてのレプリカとワーカーを含む）が新しいシークレット設定で再起動済みであることを確認してください。

実行した後は：環境変数をロールバックしたり、古いイメージに戻したりしないでください。書き換え後のデータは、現在のキーでしか開けません。
</Warning>

大規模なデータベースでは、リクエストがタイムアウトしても、サーバー側で処理が続いていることがあります。再実行しても安全です。処理済みの行はスキップされます。

ある項目の暗号鍵が公開されているデフォルト値のままの場合、その項目は拒否されます。先に`SECRET_KEY`を設定してください。

## 個人アクセストークン {#personal-access-tokens}

個人アクセストークンは再暗号化できません。再生成できるのは所有者だけです。このタブでは、有効期限が切れていないものの、現在のキーで発行されたものではないトークンを集計します。これにより、古いキーを削除できるかどうかを判断できます。

- **古いキーで発行、まだ使用可能**：これらのトークンは、古いキーを削除すると使えなくなります。
- **アップグレード前に発行、判別不可**：トークンには発行時のキーが記録されていないため、まだ使用可能なものとして扱われます。古いキーを削除する前に、これらも考慮に入れてください。
- **使用不可**：発行に使われたキーがすでに受け付けられなくなっているため、これらのトークンは現在使えません。

ここでいう古いキーとは、`BACKEND_ACCESS_TOKEN_ENCRYPTION_KEY_OLD` / `IV_OLD`に保持されているペアのことです。組み込みのデフォルト値から移行したインスタンスでは、組み込みのペアも復号用に保持されます。こちらはそのまま残り、ご自身で削除するものではありません。

トークンページでは、有効期限まで長く残っているトークンを再生成するよう、所有者に案内します。

## よくある質問

<AccordionGroup>
  <Accordion title="復号不可が0でない場合は？">
    通常は、それらの行の暗号化に使われた古い値が不足しています。その値を対応する`_OLD`変数に設定し、再起動してから、もう一度ドライランを実行してください。再暗号化ではこれらの行はスキップされ、破損することはありません。
  </Accordion>
  <Accordion title="再暗号化にダウンタイムは必要ですか？">
    再暗号化そのものには不要です。使用中のデータは、引き続き読み書きされます。シークレット設定の変更には再起動が必要です。[シークレットの収束](/ja/deploy/secret-convergence)をご覧ください。
  </Accordion>
</AccordionGroup>
