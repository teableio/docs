---
title: Credenciales e integraciones
description: Gestiona tus conexiones y secretos y concédelos a las aplicaciones y automatizaciones que los necesiten.
---

<Note>Disponible en todos los planes de Cloud; la versión autoalojada requiere el plan Business o uno superior.</Note>

Cuando una aplicación o una automatización llama a un servicio externo, usa **tus credenciales**. Las credenciales son tuyas, no de la aplicación ni de la automatización, y son de dos tipos:

- **Conexiones**: cuentas de terceros que autorizas a Teable mediante OAuth, como Google, Slack o Feishu.
- **Secretos**: cadenas que guardas tú, como una clave de API o un token de acceso.

Las credenciales se gestionan en **Ajustes** → **Integraciones** y desde ahí las concedes a cada aplicación o automatización. Una vez concedidas, todas las personas que ejecuten esa aplicación o automatización usan las credenciales de quien las concedió. El valor no se muestra a nadie y los resultados de prueba de una automatización lo enmascaran.

## Gestiona tus conexiones y secretos

Haz clic en tu avatar de la esquina inferior izquierda y abre **Ajustes** → **Integraciones**. La página tiene tres secciones: **Mis conexiones**, **Mis secretos** y **Aplicaciones de terceros que has autorizado**.

**Añadir secreto** pide:

| Campo | Descripción |
| --- | --- |
| **Clave** | Empieza por mayúscula; solo mayúsculas, dígitos y guiones bajos |
| **Valor** | De solo escritura tras guardarlo; introduce un valor nuevo para sustituirlo |
| **Descripción** | Opcional, para anotar para qué sirve el secreto |

Las conexiones se añaden con **Conectar nueva cuenta**. Cuando caduca una autorización, la conexión ofrece **Volver a conectar**.

Cada credencial indica cuántos recursos la usan ahora mismo. **Ver** abre la lista de aplicaciones y automatizaciones, donde puedes **Quitar autorización** a cualquiera de ellas.

## Conceder una credencial a una aplicación o automatización

Abre el panel de credenciales del recurso:

- **Aplicaciones**: en el panel de chat del App Builder, abre **+** → **Más** → **Credenciales y configuración**.
- **Automatizaciones**: abre el flujo de trabajo y haz clic en **Credenciales y configuración** en la pestaña **Editar**.

**Conceder** ofrece tres caminos: **Conceder un secreto existente** elige uno de tus secretos o conexiones; **Añadir secreto** crea uno y lo concede al momento; o eliges un servicio de la lista **Servicios**, que inicia un flujo de OAuth si aún no lo has conectado y lo concede directamente si está marcado como **Conectado**.

Cada concesión necesita un **Nombre de la variable**, el alias que esa credencial tiene dentro de la aplicación o automatización. Sigue las mismas reglas de nomenclatura que la clave de un secreto y es el nombre que lee el código.

El panel también puede mostrar marcadores **Sin vincular**. Copiar una aplicación, duplicar un flujo de trabajo e importar o duplicar una base traen los alias que espera el código, pero ninguna credencial. Con **Vincular la mía** aportas la tuya para que la aplicación o automatización funcione.

Cuando un alias tiene la credencial de otra persona, **Reemplazar por el mío** la sustituye por la tuya. **Solo quitar el permiso (mantener marcador)** deshace el vínculo y conserva el marcador, así que el código no cambia.

<Info>Cambiar las concesiones de un recurso exige permiso de edición sobre esa aplicación o automatización. Solo puedes conceder credenciales propias.</Info>

## Leer una credencial desde el código

| Dónde | Cómo leerla |
| --- | --- |
| Acciones de código de una automatización | Una variable de entorno, como `process.env.EXTERNAL_API_KEY` |
| Campos de entrada de una automatización | Haz clic en **Insertar secreto** junto al campo y elige un secreto concedido |
| Secretos en una aplicación | El código de servidor lee `process.env.MY_API_KEY` |
| Conexiones en una aplicación | El código de servidor llama a `getConnectionToken('ALIAS')` para obtener un token de acceso |

Si pegas algo que parece una clave en un campo de una automatización, Teable lo guarda como secreto tuyo y deja una referencia en su lugar, de modo que el texto sin formato no acaba en la configuración del flujo de trabajo. Si prefieres conservar el texto tal cual, haz clic en **Deshacer** en el aviso.

## Solicitudes de credenciales en el Chat de IA

Cuando la IA necesita una cuenta externa, fija en la conversación una tarjeta de solicitud que indica de qué servicio quiere una conexión o para qué alias quiere un secreto. Puedes:

- **Conectar mi cuenta**: iniciar un flujo de OAuth; la nueva conexión se concede automáticamente al recurso.
- **Conceder mi…**: usar una conexión o un secreto que ya tengas.
- **Omitir**: no facilitar la credencial. La IA continúa con las partes que no dependen de ella.

## Sustituir, eliminar y salir de un espacio

Antes de sustituir el valor de un secreto, eliminar un secreto o desconectar una conexión, Teable enumera las aplicaciones y automatizaciones que aún la usan. Eliminar y desconectar las deja fuera de servicio de inmediato, así que concédeles antes otra credencial si tienen que seguir funcionando. El valor anterior de un secreto no se puede recuperar.

Tras guardar un valor nuevo, una automatización lo toma en su siguiente ejecución; una aplicación, al reiniciarse su entorno de vista previa, y una aplicación publicada, solo cuando vuelves a publicarla.

Si sales de un espacio donde una aplicación o automatización sigue usando tus credenciales, la página **Integraciones** lo señala con **Saliste de este espacio**. Haz clic en **Quitar autorización** para dejar de facilitarlas.
