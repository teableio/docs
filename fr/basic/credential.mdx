Lorsqu’une application ou une automatisation appelle un service externe, elle utilise **vos identifiants**. Ceux-ci vous appartiennent et non à l’application ou à l’automatisation, et se déclinent en deux types :

- **Connexions** : comptes tiers que vous autorisez auprès de Teable, par exemple Slack, Airtable ou Google Sheets.
- **Secrets** : chaînes que vous enregistrez vous-même, par exemple une clé API ou un jeton d’accès.

Les identifiants se gèrent dans **Paramètres** → **Intégrations**, d’où vous les accordez à telle application ou telle automatisation. Une fois l’autorisation accordée, toute personne qui exécute cette application ou cette automatisation utilise les identifiants de la personne qui les a accordés. La valeur n’est montrée à personne, et les résultats de test d’une automatisation la masquent.

## Gérer vos connexions et vos secrets

Cliquez sur votre avatar en bas à gauche, puis ouvrez **Paramètres** → **Intégrations**. La page comporte trois sections : **Mes connexions**, **Mes secrets** et **Applications tierces que vous avez autorisées**.

**Ajouter un secret** demande :

| Champ | Description |
| --- | --- |
| **Clé** | Commence par une majuscule ; majuscules, chiffres et traits de soulignement uniquement |
| **Valeur** | Accessible en écriture seule après l’enregistrement ; saisissez une nouvelle valeur pour la remplacer |
| **Description** | Facultative, pour noter à quoi sert le secret |

<img
  src="/images/docs/ai/2026-10-21-credential-add-secret.png"
  alt="Add secret dialog with Key, Value, and Description filled in"
  className="docs-screenshot"
/>

Une connexion s’ajoute avec **Connecter un nouveau compte**. Saisissez un nom de service dans le champ de recherche : les services que Teable intègre lui-même figurent en haut, et le groupe **Géré par Composio** en dessous en rassemble plusieurs centaines d’autres, autorisés par Composio. Les deux types se délèguent de la même façon aux applications et aux automatisations, et aucun n’expose sa valeur ; ils diffèrent seulement par la façon dont le code de l’application les lit, décrite dans « Lire une information d’identification dans le code ».

La plupart des services se règlent en un seul passage OAuth. Un service marqué d’une icône de clé (**Se connecte avec une clé API**) ouvre à la place une boîte de dialogue de connexion et demande la clé que ce service vous a délivrée ; Composio conserve cette valeur et s’en sert pour signer chaque requête, et Teable ne la stocke pas.

Stripe prend en charge les deux modes. Son OAuth ne connecte que des comptes en mode production (live mode) : pour tester une application en mode test, choisissez **Stripe avec une clé API** dans la liste **Connecter un nouveau compte**, ou cliquez sur **Ajouter une clé API** dans votre groupe Stripe existant, puis saisissez une clé commençant par `sk_test_`. Une fois l’accès de l’application basculé sur ce compte, le code de l’application n’a pas besoin d’être modifié.

Un même service peut accueillir plusieurs comptes, par exemple une adresse Gmail professionnelle et une adresse personnelle. **Mes connexions** regroupe les comptes par service et affiche leur nombre à côté de chaque groupe. Un service déjà connecté n’apparaît plus dans la liste **Connecter un nouveau compte** ; pour y connecter un autre compte, cliquez sur **Ajouter un compte** dans le groupe de ce service. Chaque compte s’affiche sous l’adresse e-mail ou le nom d’utilisateur qu’il porte dans le service, et c’est ce nom que vous choisissez lorsque vous l’accordez à une application ou une automatisation. Autoriser à nouveau le même compte met à jour la connexion existante au lieu d’ajouter une ligne. Si le service ne renvoie aucun nom reconnaissable, utilisez **Renommer** dans le menu du compte pour lui donner un nom facile à distinguer.

Quand une autorisation expire, le compte affiche **Reconnexion requise** ; cliquez sur **Reconnecter** dans le menu du compte.

Sous chaque identifiant figure **Utilisé par N ressources**, suivi des étiquettes d’au plus trois applications ou automatisations ; cliquer sur une étiquette ouvre la ressource dans un nouvel onglet. Les autres sont regroupées derrière **+N**, qui ouvre la liste **Où elle est utilisée**, avec la date de chaque autorisation. Pour qu’une ressource n’utilise plus l’identifiant, cliquez sur le × (**Retirer l’autorisation**) de son étiquette ou de la liste, puis confirmez ; la ressource conserve un emplacement **Pas encore lié**.

## Accorder un identifiant à une application ou une automatisation

Ouvrez le panneau d’identifiants de la ressource :

- **Applications** : dans le panneau de chat de l’App Builder, ouvrez **+** → **Plus** → **Identifiants et configuration**.
- **Automatisations** : ouvrez le workflow et cliquez sur **Identifiants et configuration** dans l’onglet **Modifier le workflow**.

**Accorder** propose trois voies : **Accorder un secret existant** choisit l’un de vos secrets ou l’une de vos connexions ; **Ajouter un secret** en crée un et l’accorde aussitôt ; vous pouvez aussi choisir un service dans la liste **Services**, ce qui lance un parcours OAuth pour un service non connecté et accorde directement celui marqué **Connecté**.

<img
  src="/images/docs/ai/2026-10-21-credential-resource-panel.png"
  alt="Credentials & config panel of an automation with a placeholder that is not bound yet, a granted Gmail connection, and the Grant menu open"
  className="docs-screenshot"
/>

Chaque autorisation demande un **Nom de la variable**, l’alias de cet identifiant dans cette application ou automatisation. Les règles de nommage sont celles d’une clé de secret, et c’est ce nom que lit le code.

Le panneau peut aussi afficher des emplacements **Pas encore lié**. Copier une application, dupliquer un workflow, importer ou dupliquer un projet reprend les alias attendus par le code, mais aucun identifiant. **Lier le mien**, dans le menu ⋯ de l’emplacement, fournit les vôtres pour que l’application ou l’automatisation fonctionne.

Quand un alias porte les identifiants de quelqu’un d’autre, choisissez **Remplacer par le mien** dans le menu ⋯ de la ligne pour y mettre les vôtres. Pour rompre un lien, choisissez **Retirer** dans le menu ⋯. La boîte de confirmation comporte la case **Retirer seulement l’autorisation (garder l’emplacement)** : cochée, elle rompt le lien et conserve l’emplacement, sans toucher au code ; décochée, l’alias est supprimé aussi. Elle est cochée par défaut pour les identifiants d’autrui et décochée pour les vôtres.

Tant qu’un projet a des intégrations non connectées, un bandeau en haut de la page affiche **N intégrations ne sont pas connectées.** Cliquez sur **Connecter** pour ouvrir le panneau des intégrations et connecter un compte ou saisir une clé, ligne par ligne. Si une ligne de secret pas encore renseignée n’est plus utile, cliquez sur l’icône de suppression en fin de ligne : la ressource ne demandera plus ce secret. Fermer le bandeau ne vaut que pour les intégrations vides du moment ; il revient dès qu’une nouvelle reste ouverte. Le panneau se limite à connecter et autoriser : l’exécution d’une automatisation reste décidée par son propre interrupteur.

<Info>Modifier les autorisations d’une ressource demande le droit de modification sur cette application ou cette automatisation. Vous ne pouvez accorder que vos propres identifiants.</Info>

## Lire un identifiant dans le code

| Contexte | Comment le lire |
| --- | --- |
| Scripts d’automatisation | Variable d’environnement, par exemple `process.env.EXTERNAL_API_KEY` |
| Champs de saisie d’une automatisation | Cliquez sur **Insérer un secret** à côté du champ et choisissez un secret accordé |
| Secrets dans une application | Le code côté serveur lit `process.env.MY_API_KEY` |
| Connexions dans une application | Le code côté serveur appelle `getConnectionToken('ALIAS')` pour obtenir un jeton d’accès |
| Connexions gérées par Composio dans une application | Elles n’ont aucun jeton d’accès à échanger ; le code côté serveur appelle `callConnection('ALIAS', { ... })` et Composio signe la requête côté serveur |

Si vous collez dans un champ d’automatisation une valeur qui ressemble à une clé, Teable l’enregistre comme votre secret et laisse une référence à la place, de sorte que le texte en clair n’entre pas dans la configuration du workflow. Pour conserver le texte tel quel, cliquez sur **Annuler** dans la notification.

## Crédits des appels aux applications tierces

Appeler une application tierce via une connexion consomme les crédits de l’espace, que l’appel vienne du Chat IA, d’une application ou d’une automatisation. Ces débits figurent sous le type **Applications tierces** dans la section **Usage des crédits** de la page de facturation.

La plupart des applications coûtent très peu par appel. Celles qui facturent Teable par ressource renvoyée ou par requête, comme X, reviennent nettement plus cher pour un seul appel. Les appels en échec ne sont pas facturés, pas plus que la recherche des outils disponibles. Une fois les crédits de l’espace épuisés, ces appels sont refusés.

## Cartes d’autorisation dans le Chat IA

Quand l’IA a besoin d’un compte externe, elle épingle dans la conversation une carte intitulée **Autorisation requise pour cette tâche** et attend votre réponse avant de poursuivre le tour. Il en existe deux sortes, selon qui a besoin de l’identifiant.

**Carte de connexion** : elle apparaît quand Cuppy doit lui-même lire ou écrire dans un service pour terminer la tâche, par exemple récupérer des messages dans Gmail ou écrire dans Notion. La carte nomme le service ; cliquez sur **Connecter** pour lancer le parcours OAuth ou saisir la clé délivrée par ce service. Une fois la connexion établie, le tour reprend, et la connexion est enregistrée sous **Mes connexions**, dans **Paramètres** → **Intégrations**. Les services intégrés par Teable comme ceux gérés par Composio se connectent depuis cette carte, sans passer d’abord par la page des paramètres. **Passer** ne fournit pas la connexion et Cuppy poursuit les parties qui n’en dépendent pas. En cas d’échec, la carte affiche l’erreur : **Réessayer** relance la connexion, **Abandonner** met fin à la demande.

<img
  src="/images/docs/ai/2026-10-21-credential-chat-auth-card.png"
  alt="Authorization card above the AI chat input asking to connect Gmail, with Skip and Connect"
  className="docs-screenshot"
/>

**Carte de demande d’identifiant** : elle apparaît quand une application ou une automatisation que vous construisez a besoin de l’identifiant à l’exécution, et précise le service pour lequel elle veut une connexion, ou l’alias pour lequel elle veut un secret. Les boutons proposés dépendent de ce que vous possédez déjà :

- **Connecter …** : s’affiche si vous n’avez encore aucun compte pour ce service. Lance un parcours OAuth ; la nouvelle connexion est accordée automatiquement à la ressource. Pour un service qui se connecte avec une clé, le bouton devient **Saisir la clé …**.
- Un champ de valeur avec **Enregistrer et autoriser** : s’affiche si vous n’avez pas encore de secret pour cet alias. La valeur est enregistrée comme votre secret et accordée à la ressource.
- **Autoriser le mien** : accorde une connexion ou un secret que vous possédez déjà. Si l’alias est déjà occupé par un autre identifiant, le bouton devient **Ajouter le mien** et ajoute le vôtre sous un nouveau nom de variable ; si vous avez demandé à utiliser votre propre identifiant, il devient **Remplacer par le mien**.
- **Utiliser** / **saisir une nouvelle valeur** : s’affiche quand l’alias est déjà lié à l’un de vos propres secrets. Pour changer la valeur, cliquez sur **saisir une nouvelle valeur** ; si la valeur n’est plus valide, la carte demande directement une nouvelle valeur. **Remplacer** met à jour ce secret, et les autres ressources qui l’utilisent passent aussi à la nouvelle valeur.
- **Utiliser celui de …** : s’affiche quand l’alias porte déjà l’identifiant d’un autre membre, pour continuer à l’utiliser.
- **Ignorer** : ne pas fournir l’identifiant. L’IA poursuit les parties qui n’en dépendent pas.

Envoyer un message pendant que la carte attend la ferme également et la marque **Ignoré** ; votre message devient la consigne suivante de ce tour. Si l’identifiant reste nécessaire plus tard, demandez à Cuppy de le redemander.

Découvrez cette fonctionnalité en pratique : [exemples de workflows IA entre applications connectées](https://teable.ai/fr/blog/connect-1500-apps-to-teable-ai).

## Remplacer, supprimer et quitter un espace

Avant que vous remplaciez la valeur d’un secret, supprimiez un secret ou déconnectiez une connexion, Teable liste les applications et automatisations qui l’utilisent encore. La suppression et la déconnexion les mettent aussitôt hors service : accordez-leur d’abord un autre identifiant si elles doivent continuer à tourner. L’ancienne valeur d’un secret est irrécupérable.

Une fois la nouvelle valeur enregistrée, une automatisation la prend à sa prochaine exécution ; une application la prend au redémarrage de son environnement de prévisualisation, et une application publiée seulement après une nouvelle publication.

Si vous quittez un espace où une application ou une automatisation utilise encore vos identifiants, son étiquette sur la page **Intégrations** porte une icône d’avertissement ; survolez-la pour afficher une explication. Pour cesser de les fournir, cliquez sur le × (**Retirer l’autorisation**) de l’étiquette.
