После смены или удаления секрета сервера данные, уже находящиеся в базе данных, по-прежнему зашифрованы старым секретом. Эта страница проверяет конфигурацию секретов и переводит эти данные на текущий ключ, после чего старый секрет можно убрать. Порядок всей процедуры см. на странице [Конвергенция секретов](/ru/deploy/secret-convergence).

На странице четыре вкладки: Сохранённые шифротексты, Персональные токены доступа, JWT credentials (учётные данные JWT) и Секреты сервера. Вкладка JWT credentials описана на [отдельной странице](/ru/basic/admin-panel/jwt-credentials).

## Секреты сервера {#server-secrets}

Только для чтения. Вкладка проверяет переменные окружения и никогда не показывает значение секрета.

Здесь перечислены `SECRET_KEY`, `SANDBOX_JWT_SECRET` и каждый секрет, у которого всё ещё задана собственная переменная или переменная `_OLD`. Секрет, которого нет в списке, следует за `SECRET_KEY`, и собственная переменная ему не нужна. Когда задана `BACKEND_STORED_CREDENTIAL_ENCRYPTION_SECRET`, учётные данные, зашифрованные в базе данных, следуют уже за этой переменной; см. [Отдельный корневой секрет для сохранённых учётных данных](/ru/deploy/secret-convergence#stored-credential-root).

| Столбец | Значение |
|---|---|
| Переменная | Переменная окружения и её назначение. Переменная с меткой **Устаревший** заменена другой: пока она задана, она продолжает действовать, но в новом развёртывании задавать её не следует. **Не читается этим развёртыванием** означает, что переменная задана, но в этой редакции или конфигурации она не используется |
| Источник значения | Значение взято из самой переменной, берётся из `SECRET_KEY`, является производным от `SECRET_KEY` или представляет собой прежнее публичное значение по умолчанию. Далее следует отпечаток значения; **Публичное значение** отмечает значение, которое может вычислить кто угодно |
| `_OLD` | Заданные переменные `_OLD`, каждая со своим отпечатком. `_OLD` только проверяет или расшифровывает существующие данные |
| Как при одном SECRET_KEY | **Совпадает** означает, что удаление отдельной переменной не изменит значение. Для зашифрованного в базе данных это верно, только пока `BACKEND_STORED_CREDENTIAL_ENCRYPTION_SECRET` не задана с другим значением. **Отличается** означает, что значение изменится, поэтому сначала нужно сохранить старое |

Отпечаток — это первые 8 шестнадцатеричных символов SHA-256 значения; его можно сравнить с записью в вашем хранилище секретов.

Вверху страницы указано, сколько отдельных переменных и переменных `_OLD` всё ещё задано и сколько значений публичны, и отдельно сообщается, если `SECRET_KEY` не задан или всё ещё равен публичному значению по умолчанию.

## Сохранённые шифротексты {#stored-ciphertexts}

Перешифровывает текущим ключом шифротекст в базе данных: строки подключения арендаторов баз данных, переменные окружения приложений, конфигурацию ИИ и учётные данные сторонних сервисов. Копию шагов, по которой выполняется активная автоматизация, вкладка не перезаписывает; см. [Сколько хранить каждое старое значение](/ru/deploy/secret-convergence#old-value-retention).

1. Нажмите **Dry-run** (пробный запуск). Он только подсчитывает и ничего не меняет.
2. Проверьте результат, затем нажмите **Перешифровать**.
3. Ещё раз выполните пробный запуск и убедитесь, что и **Требует перешифрования**, и **Не расшифровывается** равны 0.

| Столбец | Значение |
|---|---|
| Всего | Строки этой таблицы, содержащие секретное значение, зашифрованное или нет |
| Актуально | Уже под текущим ключом; ничего делать не нужно |
| Требует перешифрования / Перешифровано | Строки, которые перезаписал бы пробный запуск, или строки, которые перезаписал настоящий запуск |
| Конфликты | Во время перезаписи строку изменил другой запрос, и в этот раз она пропущена. Запустите ещё раз |
| Не расшифровывается | Строку не открывает ни текущий ключ, ни одна из настроенных `_OLD`, поэтому она оставлена как есть. В результате перечислены ID этих строк, до 50 на таблицу |

Таблицы без данных по умолчанию свёрнуты.

<Warning>
Перед запуском: создайте резервную копию базы данных и переменных окружения, включая все переменные `_OLD`, и убедитесь, что каждый экземпляр приложения, включая все реплики и воркеры, перезапущен с новой конфигурацией секретов.

После запуска: не откатывайте переменные окружения и не переходите на более старый образ. Перезаписанные данные открываются только текущим ключом.
</Warning>

В большой базе данных время ожидания запроса может истечь, хотя сервер продолжает работу. Запускать повторно безопасно: уже обработанные строки пропускаются.

Если ключ шифрования какого-либо элемента всё ещё равен публичному значению по умолчанию, этот элемент отклоняется: сначала задайте `SECRET_KEY`.

## Персональные токены доступа {#personal-access-tokens}

Персональный токен доступа нельзя перешифровать; выпустить его заново может только владелец. Эта вкладка подсчитывает токены, срок действия которых не истёк, но которые выпущены не текущим ключом, чтобы вы могли понять, можно ли удалить старый ключ:

- **Старый ключ, пока работают**: эти токены перестанут работать, как только старый ключ будет удалён.
- **Выпущены до обновления, определить нельзя**: в токене не записано, каким ключом он выпущен, поэтому он считается рабочим. Перед удалением старого ключа учитывайте и их.
- **Не работают**: ключ, которым они выпущены, больше не принимается, поэтому сейчас эти токены не работают.

Старый ключ — это пара, хранящаяся в `BACKEND_ACCESS_TOKEN_ENCRYPTION_KEY_OLD` / `IV_OLD`. Экземпляр, который ушёл со встроенных значений по умолчанию, также сохраняет встроенную пару для расшифровки; она остаётся, и удалять её вам не нужно.

Страница токенов предлагает владельцам заново выпустить те из них, у которых остаётся долгий срок действия.

## Часто задаваемые вопросы

<AccordionGroup>
  <Accordion title="Что делать, если «Не расшифровывается» не равно 0?">
    Обычно не хватает старого значения, которым были зашифрованы эти строки. Поместите его в соответствующую переменную `_OLD`, перезапустите и снова выполните пробный запуск. Перешифрование пропускает эти строки и не повреждает их.
  </Accordion>
  <Accordion title="Нужен ли простой для перешифрования?">
    Само по себе — нет: используемые данные продолжают читаться и записываться. А вот смена конфигурации секретов требует перезапуска; см. [Конвергенция секретов](/ru/deploy/secret-convergence).
  </Accordion>
</AccordionGroup>
