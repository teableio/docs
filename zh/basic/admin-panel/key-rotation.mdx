<Tip>适用于私有化部署 Business 及以上版本</Tip>

路径：系统管理 → 密钥轮换

更换或去掉某个服务端密钥之后，库里已有的数据仍然是用旧密钥加密的。这个页面用来核对密钥配置，把这些数据换到当前密钥下，之后才能移除旧密钥。完整的操作顺序见[密钥收敛](/zh/deploy/secret-convergence)。

页面有四个标签：库内密文、个人访问令牌、JWT 凭据、服务端密钥。「JWT 凭据」标签另见[单独的说明](/zh/basic/admin-panel/jwt-credentials)。

## 服务端密钥 {#server-secrets}

只读，用来核对环境变量的配置，不显示任何密钥的值。

列出的是 `SECRET_KEY`、`SANDBOX_JWT_SECRET`，以及还设着专属变量或 `_OLD` 变量的密钥。没列出的密钥都跟随 `SECRET_KEY`，不需要单独设置。设置了 `BACKEND_STORED_CREDENTIAL_ENCRYPTION_SECRET` 之后，库里加密保存的凭据改为跟随它，见[给库内凭据单独设一个根密钥](/zh/deploy/secret-convergence#stored-credential-root)。

| 列 | 含义 |
|---|---|
| 变量 | 环境变量名和用途。带「待废弃」标签的变量已经被取代：设着仍然生效，新部署不要设置；「本部署不读取」表示这个变量设了，但这个版本类型（社区版、企业版等）或当前配置用不到它 |
| 取值来源 | 值来自专属变量、回落到 `SECRET_KEY`、由 `SECRET_KEY` 派生，还是内置的公开默认值。后面是取值的指纹；带「公开值」标记时，这个值任何人都能算出来 |
| `_OLD` | 已设置的 `_OLD` 变量和各自的指纹。`_OLD` 只用来验证或解密旧数据 |
| 与只设 SECRET_KEY 时相同 | 「相同」表示删掉专属变量不会改变取值（对库内密文，前提是 `BACKEND_STORED_CREDENTIAL_ENCRYPTION_SECRET` 没有设成别的值）；「不同」表示删掉后取值会变，需要先保留旧值 |

指纹是取值 SHA-256 的前 8 位十六进制，可以拿来和密钥管理系统里的记录对照。

页面顶部会汇总还设着几个专属变量、几个 `_OLD` 变量，其中有几个取值是公开值；`SECRET_KEY` 未设置或仍是公开默认值时会单独提示。这时还会提示：已有数据的实例要先按启动日志加上对应的 `_OLD` 变量，再设置新值。

## 库内密文 {#stored-ciphertexts}

把库里的密文重加密到当前密钥下，包括数据库租户的连接串、应用环境变量、AI 配置和第三方凭据。运行中的自动化使用的那份步骤副本不会被改写，见[各个旧值要保留多久](/zh/deploy/secret-convergence#old-value-retention)。

1. 点 **试运行**。它只统计，不修改数据。
2. 确认结果后点 **重加密**。
3. 再试运行一次，确认「待重加密」和「无法解密」都是 0。

| 列 | 含义 |
|---|---|
| 总行数 | 这张表里保存着密钥类取值的行数，不论是否已经加密 |
| 已是最新 | 已经在当前密钥下，不需要处理 |
| 待重加密 / 已重加密 | 试运行时是将要改写的行数，正式执行后是已经改写的行数 |
| 并发冲突 | 改写时这一行同时被别的请求修改，本次跳过。再执行一次即可 |
| 无法解密 | 用当前密钥和已配置的 `_OLD` 都解不开，保持原样。结果里会列出这些行的 ID，每张表最多 50 个 |

没有数据的表默认收起。

<Warning>
执行前：备份数据库和环境变量（包括所有 `_OLD` 变量），并确认每个应用实例（包括所有副本和 worker）都已经用新的密钥配置重启。

执行后：不要回滚环境变量，也不要降级镜像。重写后的数据只能用当前密钥解开。
</Warning>

数据量大时请求可能超时，但服务端会继续处理。再次执行是安全的，已经处理过的行会跳过。

某一项的加密密钥仍是公开默认值时，这一项会被拒绝重加密：先设置 `SECRET_KEY`。

### 自动化凭据 {#automation-credentials}

在表格下方。它检查自动化步骤和发布版本里是否还有直接保存的邮箱密码和 Webhook 密钥（上面的重加密不处理这部分），并在你确认后迁移。

1. 点 **检查并迁移**。检查本身不修改数据。
2. 发现有可迁移的内容时，在弹出的确认框里确认。每个邮箱密码会变成一条归某位成员所有、并授权给该自动化的 Secret：优先是步骤的最后编辑者，其次是仍为空间所有者的创建者，否则是加入最早的空间所有者。Webhook 密钥单独存放。自动化照常运行。
3. 查看结论。这里已经没有剩余、上面的试运行也没有待重加密的行时，就可以移除第三方凭据的旧密钥。

迁移不了的保持原样，并写明原因：找不到可以持有 Secret 的成员、无法解密，或者自动化处于关闭状态（开启后再执行一次）。

## 个人访问令牌 {#personal-access-tokens}

个人访问令牌不能重加密，只能由持有者重新生成。这个标签统计还没过期、但不是用当前密钥签发的令牌，用来判断旧密钥还能不能删：

- **旧密钥签发、仍然能用**：删掉对应的旧密钥之后，这些令牌会停用。
- **升级前签发、无法判断**：令牌里没有记录签发时用的密钥，按仍然能用处理。删掉旧密钥之前也要把它们考虑进去。
- **已停用**：签发它们的密钥已经不再被接受，这些令牌现在就不能用。

这里的旧密钥指 `BACKEND_ACCESS_TOKEN_ENCRYPTION_KEY_OLD` / `IV_OLD` 里保留的那一组。从内置默认值换过来的实例，内置的那一组也会自动保留用于解密，它一直保留，不需要你删除。

令牌页会建议持有者重新生成其中有效期较长的令牌。

## 常见问题

<AccordionGroup>
  <Accordion title="「无法解密」不是 0 怎么办？">
    通常是缺了加密这些行时使用的旧值。把它放进对应的 `_OLD` 变量，重启后再试运行。重加密会跳过这些行，不会破坏它们。
  </Accordion>
  <Accordion title="重加密需要停机吗？">
    重加密本身不需要停机，正在使用的数据会照常读写。更换密钥配置需要重启实例，见[密钥收敛](/zh/deploy/secret-convergence)。
  </Accordion>
</AccordionGroup>
