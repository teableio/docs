<Note>Available on all Cloud plans; Self-Hosted requires Business or higher.</Note>

A routine hands an objective to Cuppy, Teable’s AI assistant, to carry out repeatedly, either on a schedule or whenever a connected third-party app reports an event. That suits work nobody needs to trigger by hand: a daily report, a periodic cleanup of expired records, filing a new email as it arrives. Every run is a full AI chat, so a routine can do everything AI chat can, including reading and writing tables, calling skills, and producing files.

A routine is a resource inside a project and sits in the left sidebar next to tables, apps, and automations.

<Info>An automation runs the steps you configured in advance, while a routine hands the agent an objective to work out for itself. Both can fire on a schedule, and both can fire on an event from a connected third-party app. Use an automation when you need fixed steps and predictable output; use a routine when you want the agent to decide what to do with the current data each time.</Info>

## Create a Routine

<Steps>
  <Step title="Create">
    In the left sidebar, click **+** and choose **New routine**.
  </Step>
  <Step title="Write the objective">
    A new routine opens straight on the **Edit routine** page. Describe what each run should do in **Routine objective**. The objective is the entire instruction for a run, so state where the data comes from, how to process it, and where the result goes. For example, "Summarize records added to the Tasks table yesterday, group them by owner, and write the summary to the Daily Report table."
  </Step>
  <Step title="Choose the trigger">
    Under **Trigger**, choose **On a schedule** or **On a connector event**, then fill in the settings that kind needs.
  </Step>
  <Step title="Activate">
    Click **Activate** in the notice at the top of the page, or turn on the switch to the left of the name. The configuration saves automatically but must be complete before you activate: **On a schedule** needs a future occurrence, and **On a connector event** needs a usable account.
  </Step>
</Steps>

For examples of this feature in use, read [scheduled AI task examples](https://teable.ai/blog/run-ai-tasks-on-a-schedule).

## Settings

Besides the objective and the trigger, the **Edit routine** page carries these settings:

| Setting | Description |
| --- | --- |
| **Model** | The model and effort level this routine runs on. The button shows the current choice, such as Smart Medium. A new routine starts with the model and effort level you last picked in AI chat, or the defaults if you have not picked any |
| **Chat** | **New chat for every run** keeps runs independent of each other; **Continue the previous run's chat** carries the context of earlier runs forward, which suits work that needs to refer to the last result |

The model and effort level are saved with the configuration, and every run uses that saved choice. Switching models in AI chat later does not change it. If the saved model is no longer offered, runs fall back to the default model.

### Trigger

**On a schedule** runs the routine at the times you set, configured under Schedule below.

**On a connector event** runs it once whenever a connected third-party app reports an event, such as a new email or a new issue. Pick the app, the event, the **Account** that receives it, and whatever parameters the event takes; it is configured exactly like the automation trigger, described in [When Connector Event Received](/en/basic/automation/trigger/external/connector-event). A routine on this trigger has no **Next run** time and does not use **Schedule**.

If the account grant is revoked, the connected account is removed, or the app stops the subscription, the routine reports **Subscription disconnected** and stops receiving events, and Teable notifies the routine's owner. Reconnecting the same account rebuilds the subscription on its own; to use a different one, pick another account and save.

### Schedule

**Schedule** is used by **On a schedule** only. Pick a frequency from the presets: **Hourly** at a given minute, **Daily** and **Weekdays** at a given time, **Weekly** on a weekday and time, **Monthly** on a day and time.

For anything more specific, choose **Custom (RRULE)** and write an RFC 5545 rule, such as `FREQ=DAILY;BYHOUR=9;BYMINUTE=0`. A custom rule has these limits:

- The frequency must be `HOURLY`, `DAILY`, `WEEKLY`, `MONTHLY`, or `YEARLY`, and two runs must be at least 1 hour apart.
- You can use `INTERVAL`, `COUNT`, `BYDAY`, `BYMONTHDAY`, `BYMONTH`, plus one `BYMINUTE` and one `BYHOUR`. `COUNT` tops out at 1000.
- The timezone and start time belong to the routine, so `TZID`, `DTSTART`, `UNTIL`, and `BYSECOND` are rejected.

For a schedule that runs only once, use a custom rule with `COUNT=1`.

A schedule is evaluated in the routine's timezone. That timezone is taken from whoever first configures the routine and does not follow later editors or viewers. The **Next run** time shown in the interface is already converted to your local time.

## Drafts, Updates, and Running Now

A new routine is a draft and does not run by itself until you activate it. To change the configuration, click **Edit** in **Routine details** on the routine page to open the **Edit routine** page. When you edit an active routine, changes are saved automatically as a draft while the live version keeps running on the old configuration. A notice at the top of the page flags the unpublished changes: click **Update** to apply them, or **Discard changes** to drop them.

**Run now** executes once without waiting for the trigger, which is useful for testing the objective. A routine cannot be run by hand again until its previous run has finished.

On a connector-event routine that is not yet active, **Run now** shows **Waiting for an event** instead: go into the app and do something that fires the event, and Teable uses the one it receives for a single run, which then appears in routine history. Click **Stop waiting** to end the wait early. An active routine already receives its events, so it neither needs nor allows this.

Turn the switch off to deactivate. The routine stops firing, and existing routine history is kept.

## Routine History

Open a routine to see **Routine details** on one side, summarizing the objective, trigger, next run time, model, and chat mode, and **Routine history** on the other, which lists every run in time order under the name of its conversation.

<img
  src="/images/docs/ai/2026-10-22-routine-page.png"
  alt="Routine page: Routine history on the left lists the conversation of each run; Routine details on the right shows the objective, trigger, next run time, model, and chat mode"
  className="docs-screenshot"
/>

Click a run to open its full conversation in the chat area. Members who can edit the routine can continue the conversation there; other members can only view it. A run whose conversation has been deleted shows **This conversation was deleted**.

Runs that hit an error and runs that were skipped are both marked as failed in the list. Hover over a run to see the reason; each reason calls for a different response:

| Message | Meaning | What to do |
| --- | --- | --- |
| **Run failed** | The run started but hit an error | Open the conversation for that run and judge from the failure point whether the objective or the data is at fault |
| **Skipped: not enough credits** | Credits ran out, so the run never started | Top up the space's credits |
| **Skipped: the previous run was still in progress** | The previous run had not finished, so this occurrence was skipped | Lower the frequency, or reduce how much one run processes |
| **Skipped: timed out waiting in the queue** | The run waited too long in the queue and was skipped | Occasional occurrences need no action; a recurring one means too much is scheduled at the same time, so stagger the schedules |
| **Skipped: AI agent unavailable** | The AI agent runtime was under maintenance or not configured, so the run never started | Runs resume once maintenance ends; if it keeps happening, contact your administrator |

Each run's conversation also appears in the chat history of the routine's owner. Scheduled and manual runs carry the routine's name; event-triggered runs are renamed automatically based on the objective and the event received, so each event is easy to tell apart in the history. Deleting a routine does not delete these conversations: they keep their names and become ordinary chats.

<Info>A project's owner and creator can create, edit, and delete routines; other collaborators have read access. Every collaborator can view routine history and the conversation of each run. With the **Authority Matrix** enabled, members see routine history only for the routines they are granted.</Info>

## Owner

A routine runs as its owner: each run's conversation belongs to the owner, and failure and disconnection notifications go to the owner too. The **Last updated by** label at the top of the page shows the owner.

A new routine's owner is its creator. After that, the owner is whoever most recently activated the routine or clicked **Update** to publish changes. Saving a draft, renaming, or deactivating does not change the owner.

If the owner can no longer edit the routine, for example because their account was deactivated, they were removed from the project or space, or they lost edit permission, the routine passes automatically to the member who has been an owner of the project (or its space) the longest, and keeps running.

## Failure Alerts and Automatic Deactivation

When a run fails or credits run out, Teable notifies the routine's owner, named under **Notifications will be sent to** at the top of the routine history list. Failure notifications are not sent every single time, so that a long run of failures does not flood the recipient.

After 5 consecutive failures the routine is deactivated automatically and a separate notification goes out. Turn the switch back on once the problem is fixed; the count resets after the next successful run.

Not every unsuccessful run counts toward that total: runs skipped because the previous run was still in progress, because they timed out in the queue, or because the AI agent was unavailable, along with canceled runs (someone interrupted the run, or the routine or its project was deleted), are not failures and produce no notification. A credit shortfall does count, so leaving credits unfunded eventually deactivates the routine.

## FAQ

<AccordionGroup>
  <Accordion title="Do routines consume credits?">
    Yes. Every run is an AI chat and is billed against the space's credits by actual usage, listed under type **Routine** in **Credit usage summary** on the billing page. When credits run out the run is skipped and a notification is sent, and repeated skips eventually deactivate the routine.
  </Accordion>

  <Accordion title="If I edit the objective, does it affect the run that is in progress?">
    No. The change is saved as a draft and only reaches the live version when you click **Update**. A run already under way keeps the configuration it started with.
  </Accordion>

  <Accordion title="Do routines in a project installed from a template run automatically?">
    Scheduled ones do. After a template install they are switched on the way its workflows are, and a schedule with no future occurrence stays a draft. Connector-event routines are not switched on: credentials do not come over with a template, so pick one of your own accounts before activating.
  </Accordion>

  <Accordion title="With Continue the previous run's chat, does the context grow without limit?">
    When the context approaches its limit, Teable compacts the conversation, so runs are not interrupted by it. Choose **New chat for every run** when each run should start from a clean context.
  </Accordion>
</AccordionGroup>
