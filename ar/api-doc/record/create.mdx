### المسار

POST /api/table/\{tableId\}/record

### الطلب

#### معلمات المسار

* tableId (string): المعرّف الفريد للجدول.

#### نص الطلب

* **records (مطلوب)**
  * الوصف: مصفوفة السجلات المطلوب إنشاؤها
  * النوع: مصفوفة
  * مثال:
    ```json
    [
      {
        "fields": {
          "Name": "John Doe",
          "Age": 30,
          "Email": "john@example.com"
        }
      },
      {
        "fields": {
          "Name": "Jane Smith",
          "Age": 28,
          "Email": "jane@example.com"
        }
      }
    ]
    ```
  * ملاحظة: كل سجل عبارة عن عنصر يحتوي على كائن `fields`. ويحتوي كائن `fields` على أسماء الحقول وقيمها المقابلة. لكل نوع من الحقول بنية قيمة مختلفة؛ راجع [أنواع قيم حقول السجلات](/ar/api-doc/record/interface) للاطلاع على التفاصيل.
  * القيم الافتراضية: تستخدم الحقول المحذوفة من `fields` القيمة الافتراضية للجدول عند تهيئة إحداها. إذا لم تكن للحقل المطلوب قيمة افتراضية، أو إذا مرّرت `null` صراحةً إلى حقل مطلوب، فسيفشل الطلب.
* **fieldKeyType (اختياري)**
  * الوصف: يحدد نوع مفتاح الحقل
  * النوع: سلسلة نصية
  * القيم الممكنة:
    * "name": استخدام اسم الحقل كمفتاح
    * "id": استخدام معرّف الحقل كمفتاح
    * "dbFieldName": استخدام dbFieldName للحقل كمفتاح
  * مثال: `"name"` أو `"id"` أو `"dbFieldName"`
  * ملاحظة: إذا لم تحدده، فسيُستخدم اسم الحقل كمفتاح افتراضيًا.
  * الاستخدام:
    * عند ضبطه على "name":
      ```json
      {
        "fields": {
          "Name": "John Doe",
          "Age": 30
        }
      }
      ```
    * عند ضبطه على "id":
      ```json
      {
        "fields": {
          "fldABCDEFGHIJKLMN": "John Doe",
          "fldOPQRSTUVWXYZ12": 30
        }
      }
      ```
* **typecast (اختياري)**
  * الوصف: يحدد ما إذا كانت أنواع قيم الحقول ستُحوّل تلقائيًا. يُطبّق التحقق الصارم افتراضيًا، ما يفرض تطابق قيم الإدخال مع نوع بيانات الحقل الحالي. عند تمكينه، سيحاول النظام إجراء التحويل تلقائيًا.
  * النوع: قيمة منطقية
  * القيم الممكنة: true أو false
  * مثال: `true`
  * ملاحظة: إذا ضُبط على true، فسيحاول النظام تحويل قيم الإدخال إلى نوع قيمة الحقل الصحيح.
  * أمثلة على الاستخدام:
    * حقل ارتباط: يمكن استخدام نص المفتاح الأساسي مباشرةً لإنشاء الارتباط
      ```json
      {
        "User table": "John Smith"
      }
      ```
    * حقل تاريخ: يمكن استخدام سلاسل تاريخ بتنسيق غير قياسي
      ```json
      {
        "Date": "2023-05-15"
      }
      ```
    * حقل مستخدم: يمكن استخدام اسم المستخدم مباشرةً
      ```json
      {
        "Assigned To": "John Doe"
      }
      ```
* **order (اختياري)**
  * الوصف: يحدد موضع السجلات الجديدة في طريقة عرض محددة
  * النوع: كائن
  * الخصائص:
    * viewId
      * الوصف: معرّف طريقة العرض [(كيفية الحصول عليه)](/ar/api-doc/get-id#viewid)
      * النوع: سلسلة نصية
      * مثال: `"viwABCDEFGHIJKLMN"`
    * anchorId
      * الوصف: معرّف السجل المرجعي [(كيفية الحصول عليه)](/ar/api-doc/get-id#recordid)
      * النوع: سلسلة نصية
      * مثال: `"rec123456789ABCDE"`
    * position
      * الوصف: الموضع بالنسبة إلى السجل المرجعي
      * النوع: سلسلة نصية
      * القيم الممكنة:
        * "before": قبل السجل المرجعي
        * "after": بعد السجل المرجعي
      * مثال: `"after"`
  * مثال كامل:
    ```json
    {
      "viewId": "viwABCDEFGHIJKLMN",
      "anchorId": "rec123456789ABCDE",
      "position": "after"
    }
    ```
  * ملاحظة: يتيح استخدام order التحكم الدقيق في مواضع السجلات الجديدة ضمن طريقة عرض محددة.

### الاستجابة

#### استجابة النجاح

* رمز الحالة: 201 Created
* نص الاستجابة: يُرجع بيانات السجلات التي أُنشئت.

**مثال على نص الاستجابة**

```json
{
  "records": [
    {
      "id": "record789",
      "fields": {
        "single line text": "قيمة نصية 1"
      }
    },
    {
      "id": "record567",
      "fields": {
        "single line text": "قيمة نصية 2"
      }
    }
  ]
}
```

### استجابات الأخطاء

* رمز الحالة: 400 Bad Request: خطأ في تنسيق نص الطلب أو غياب الحقول المطلوبة.
* رمز الحالة: 404 Not Found: قيمة tableId المحددة غير موجودة.

## إنشاء السجلات أو تحديثها حسب حقل فريد {#upsert-by-unique-field}

عند مزامنة بيانات خارجية، يمكنك مطابقة السجلات بقيمة فريدة مثل رقم الطلب أو رقم العميل، دون البحث أولًا عن معرّفات السجلات.

```text
POST /api/table/{tableId}/record/upsert
```

<Info>تتطلب هذه الواجهة جدولًا يستخدم محرك v2، ولا تدعم الاستدعاء عبر العروض المشتركة. يتطلب وضع `error` إذن إنشاء السجلات؛ ويتطلب وضعا `ignore` و`update` إذني الإنشاء والتحديث معًا.</Info>

### نص الطلب

| المعامل | الوصف |
| --- | --- |
| `matchField` | مطلوب. معرّف حقل المطابقة، ويجب تفعيل قيد التفرد عليه. يُدعم حقل واحد فقط، ولا تُدعم المفاتيح المركبة. |
| `onConflict` | مطلوب. طريقة التعامل مع تطابق موجود؛ راجع الجدول أدناه. |
| `records` | مطلوب. سجل واحد على الأقل. يقدم كل سجل قيمه في `fields`، ويجب أن يتضمن قيمة مطابقة غير فارغة. لا يجوز تكرار قيم المطابقة داخل الطلب نفسه. |
| `fieldKeyType` | اختياري. نوع المفاتيح في `fields`، كما في واجهة إنشاء السجلات. استخدم دائمًا معرّف الحقل في `matchField`. |
| `typecast` | اختياري. ما إذا كان ينبغي محاولة تحويل أنواع قيم الحقول تلقائيًا، كما في واجهة إنشاء السجلات. |

تُنشأ السجلات التي لا تطابق سجلًا موجودًا. وعند وجود تطابق، يُطبّق `onConflict`:

| القيمة | السلوك |
| --- | --- |
| `error` | يفشل الطلب بأكمله إذا كانت أي قيمة مطابقة موجودة بالفعل. |
| `ignore` | يحتفظ بالسجل الحالي ويتخطى سجل الإدخال هذا. |
| `update` | يحدّث الحقول المقدمة فقط؛ وتحتفظ الحقول الأخرى بقيمها. |

على سبيل المثال، إذا كان `fldOrderNumber` حقل رقم طلب مع تفعيل قيد التفرد، فإن الطلب التالي ينشئ طلبًا جديدًا أو يحدّث حالة طلب موجود:

```json
{
  "fieldKeyType": "id",
  "matchField": "fldOrderNumber",
  "onConflict": "update",
  "records": [
    {
      "fields": {
        "fldOrderNumber": "ORDER-001",
        "fldStatus": "مدفوع"
      }
    }
  ]
}
```

### الاستجابة

في الاستجابة الناجحة، يتبع `results` ترتيب الإدخال، ويبدأ `index` من 0. ويحصي `summary` السجلات المطلوبة وكل نوع من النتائج.

| `status` | المعنى |
| --- | --- |
| `created` | تم إنشاء سجل جديد. |
| `updated` | تم تحديث سجل موجود. |
| `unchanged` | القيم الحالية مطابقة بالفعل، أو لا توجد حقول تحتاج إلى تحديث. |
| `skipped` | تم تخطي سجل موجود في وضع `ignore`. |

تتضمن النتائج `recordId` و`record` فقط عندما يملك المستدعي إذن قراءة ذلك السجل. ويظل محتوى الحقول خاضعًا لأذونات القراءة.

```json
{
  "results": [
    {
      "index": 0,
      "status": "updated",
      "recordId": "recExample",
      "record": {
        "id": "recExample",
        "fields": {
          "fldOrderNumber": "ORDER-001",
          "fldStatus": "مدفوع"
        }
      }
    }
  ],
  "summary": {
    "requested": 1,
    "created": 0,
    "updated": 1,
    "unchanged": 0,
    "skipped": 0
  }
}
```
