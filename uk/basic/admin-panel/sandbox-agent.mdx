Шлях: Панель адміністратора → Sandbox Agent

Сторінка **Sandbox Agent** містить вкладки **Налаштування** й **Пісочниці** для налаштування роботи AI Chat у пісочницях.

<Info>Для самостійного розгортання спочатку розгорніть повнофункціональне середовище виконання. Див. розділ [Архітектура](/uk/deploy/architecture).</Info>

## Загальні налаштування

Налаштуйте обмеження середовища виконання в розділі **Загальні налаштування** на вкладці **Налаштування**:

| Налаштування | Опис |
|------|------|
| **Час очікування неактивного потоку** | Визначає, коли неактивний потік завершується |
| **Час очікування бездіяльності** | Визначає, коли неактивна пісочниця перезапускається |
| **Обмеження одночасних чатів** | Визначає, скільки агентів кожен користувач може запускати одночасно. AI Chat і App Builder також є агентами |
| **Рівень міркування** | Визначає стандартну інтенсивність міркування агентів |
| **Режим обслуговування** | Коли режим увімкнено, AI Chat, створення застосунків, попередні перегляди й рутини не починають нових раундів, а ті, що вже виконуються, завершуються звичайним чином. Вмикайте його перед оновленням або обслуговуванням екземпляра |
| **Повідомлення про обслуговування** | Показується користувачам разом із повідомленням про технічні роботи, поки режим обслуговування ввімкнено. Поясніть у ньому причину й очікуваний час відновлення роботи |

## Ресурси пісочниці

У розділі **Sandbox resources** на вкладці **Налаштування** спершу задайте для кожної пісочниці стандартні значення **Кількість vCPU**, **Memory** і **Temporary Disk**.

Щоб виділити певному виду роботи інші ресурси, заповніть відповідні клітинки в таблиці **Per-scenario settings**. Для порожніх клітинок використовуються стандартні значення.

| Сценарій | Як використовується пісочниця |
|------|------|
| **AI чат** | Розмова з AI у Проєкті. Одна на користувача, спільна для всіх його чатів |
| **Конструктор застосунків** | Створення й попередній перегляд застосунків. Одна на застосунок |
| **IM-бот** | Відповіді на повідомлення у Feishu, Slack і Telegram. Одна на бота |
| **Рутина** | Запуск рутин за розкладом. Одна на рутину |

Наприклад, якщо попередній перегляд застосунків часто завершується помилкою через нестачу пам’яті, збільште пам’ять лише для сценарію **Конструктор застосунків**, не зачіпаючи інших. Перед збереженням діалог підтвердження перелічує всі зміни, зокрема сценарії, які досі успадковують стандартні значення й тому змінюються разом із ними.

Нові налаштування застосовуються лише до пісочниць, створених після збереження; запущені пісочниці зберігають поточні ресурси. Щоб застосувати налаштування одразу, пакетно видаліть потрібні пісочниці за типом на вкладці **Пісочниці**.

## Вкладка «Пісочниці»

Використовуйте вкладку **Пісочниці**, щоб переглядати поточні сеанси пісочниць і керувати ними. Їх можна фільтрувати за статусом, типом та іншими умовами.

Завершення активних сеансів перериває поточну роботу агента або попередній Перегляд застосунку. Перш ніж продовжити, виконайте вказівки щодо підтвердження в інтерфейсі продукту. Натискання **Пакетне видалення** видаляє всі пісочниці, що відповідають поточним фільтрам; для підтвердження потрібно ввести `DESTROY`. Посилання на попередній перегляд розгорнутих застосунків одразу перестають працювати, доки власник застосунку знову не відкриє чат.
