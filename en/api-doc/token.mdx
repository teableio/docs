Personal Access Tokens are best for scripts, internal tools, and server-side integrations.

If you're building a multi-tenant integration for external users, use OAuth instead: see [OAuth App](/en/api-doc/oauth).

## Create a token

1. Click your avatar at the bottom left, then open **Settings** → **Developer tools** → **Personal access tokens** (or go directly to the [token management page](https://app.teable.ai/setting/personal-access-token)) and click **Create new token**.

2. Choose an expiration period for your token. Note that this period cannot be modified once set.

3. Under **Permissions**, choose a preset. New tokens start on **Build**:

   | Preset | What it can do |
   | --- | --- |
   | **Read only** | View and export, change nothing |
   | **Edit data** | Create, update and delete records, but not the table structure |
   | **Build** | Build tables, change fields, and set up automations and apps; cannot manage members or spaces. Suited to AI agents and the CLI |
   | **Full access** | Everything you can do in the space, including inviting members and deleting spaces |

   To fine-tune it, expand **Customize each part** and set **Data**, **Structure**, **Automations & apps**, and **Spaces & members** to **None**, **Read**, or **Write**. A token can never do more than your own role allows in a space.

4. Under **Access**, choose **All spaces and projects** to give the token access to all current and future spaces and projects. To limit it to some of them, choose **Specific spaces or projects**, then click **Add project or space** to pick them.

## Use the token

Send the token in the `Authorization` header:

```bash
curl -H 'Authorization: Bearer __token__' \
  'https://app.teable.ai/api/table/__tableId__/record'
```

Need help finding IDs like `tbl...`? See [Getting IDs](/en/api-doc/get-id).
