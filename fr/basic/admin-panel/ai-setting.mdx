Chemin : Administration système → Paramètres d’IA

La page **Paramètres d’IA** permet de configurer le **Chat IA**, les **Champs IA**, l’**Automatisation IA** et le **Générateur d’Applications**. En haut de la page se trouve l’interrupteur **Capacités IA** ; en dessous, la configuration se fait dans l’ordre via les onglets **Modèles**, **Chat IA** et **Générateur d’applications**. Chaque onglet dépend du précédent : tant que celui-ci n’est pas terminé, la page indique les réglages qui manquent encore. Le panneau **Configuration en attente** à droite liste les éléments requis manquants ; un clic sur l’un d’eux ouvre l’onglet et l’étape correspondants.

## Avant de commencer

Avant d’ouvrir la page Paramètres d’IA, assurez-vous que les éléments suivants sont prêts.

| Exigence | Requise ? | Remarques |
|------|------|------|
| **Configuration de l’environnement d’exécution des agents** | Requise pour le Chat IA et le Générateur d’Applications | Utilisée par le Chat IA et le Générateur d’Applications |
| **Fournisseur personnalisé** | Requis lorsque le Chat IA ou le Générateur d’Applications utilise votre propre clé (BYOK) | Utilisez un fournisseur **Compatible OpenAI** ou **Anthropic** |
| **Clé API OpenAI** | Facultative | Nécessaire uniquement si vous souhaitez activer la **Saisie vocale** dans le Chat IA |
| **Accès public** | Requis lorsque le moteur de déploiement **Vercel** est sélectionné | Votre **instance Teable** et votre **stockage d’objets (MinIO / S3)** doivent être accessibles publiquement par Vercel |

## Étapes de configuration

Dans l’onglet **Modèles**, l’assistant de configuration comporte trois étapes pour connecter et choisir les modèles. Les étapes terminées sont repliées par défaut ; cliquez sur une étape pour la déplier et la modifier :

<Steps>
  <Step title="Configurer l’API LLM">
    Configurez la connexion à votre modèle et effectuez le test initial.
  </Step>
  <Step title="Configurer les modèles recommandés">
    Choisissez les modèles recommandés pour les Champs IA et l’Automatisation IA.
  </Step>
  <Step title="Définir le modèle de chat">
    Choisissez un modèle pour chacun des quatre niveaux de modèle de chat.
  </Step>
</Steps>

Le Chat IA et le Générateur d’Applications nécessitent aussi un environnement d’exécution et le déploiement des Applications, qui se configurent respectivement dans les onglets **Chat IA** et **Générateur d’applications**. Choisissez d’abord une [option de déploiement](/fr/deploy/choose) et terminez le déploiement, puis suivez les instructions ci-dessous.

### Configurer l’API LLM

À l’étape **Configurer l’API LLM**, cliquez sur **Ajouter un fournisseur LLM** pour ajouter un fournisseur de modèles, puis testez ses modèles. Si vous utilisez votre propre clé (BYOK), choisissez **Compatible OpenAI** ou **Anthropic** comme type de fournisseur.

La fenêtre de contexte et la sortie maximale par réponse sont déterminées automatiquement par le **Catalogue de modèles** ; rien n’est à saisir. Pour vérifier les valeurs obtenues pour un modèle, ouvrez **Catalogue de modèles**, choisissez une **Portée** dans **Inspecter un modèle**, puis sélectionnez le modèle ; **Détail des paramètres** affiche alors le contexte, la sortie max. et l’origine de chaque valeur.

Lorsque le catalogue ne contient aucune entrée correspondante (un modèle récemment publié ou auto-hébergé, par exemple), le modèle fonctionne avec les valeurs définies sous **Aucune correspondance** dans **Règles de correspondance** : par défaut, une fenêtre de contexte de 200000 et une sortie maximale de 32000, **Détail des paramètres** indiquant **Règle de correspondance** comme origine des deux. Si ces valeurs ne conviennent pas au modèle, ajustez-les dans **Règles de correspondance**, puis cliquez sur **Sauvegarder**.

### Configurer les modèles recommandés

Choisissez les modèles recommandés que les utilisateurs peuvent sélectionner dans les **Champs IA** et l’**Automatisation IA**.

### Définir le modèle de chat

Dans **Niveaux de modèle de chat**, choisissez un modèle pour **Ultra**, **Smart**, **Standard** et **Lite** ; les modèles proposés sont répartis selon leur origine en deux groupes, **Vercel AI Gateway** et **Fournisseur personnalisé**, le groupe **Vercel AI Gateway** ne contenant que les modèles recommandés activés à l’étape 2. Les utilisateurs choisissent par niveau dans le menu de modèles du **Chat IA** de la barre latérale et voient le nom du niveau plutôt que celui du modèle : vous pouvez donc remplacer à tout moment le modèle associé à un niveau sans incidence pour ceux qui l’ont déjà sélectionné.

| Niveau | Description |
|------|------|
| **Ultra** | Capacité maximale, pour les tâches exigeantes. Laissé vide, il affiche **Non proposé** et n’apparaît pas dans le menu de modèles des utilisateurs.|
| **Smart** | Le modèle principal. Les Champs IA, les tâches en arrière-plan et tout niveau sans modèle propre l’utilisent ; il doit être défini.|
| **Standard** | Conversations courantes et tâches générales, également utilisé pour les tâches en arrière-plan intermédiaires. Laissé vide, il reprend **Smart**.|
| **Lite** | Travail courant à faible coût et à forte fréquence, également utilisé pour les tâches légères comme la génération des titres de conversation. Laissé vide, il reprend **Smart**.|

Deux commandes supplémentaires figurent à droite de chaque niveau :

- **Définir par défaut** : le niveau proposé aux utilisateurs à l’ouverture du menu de modèles. Un **Ultra** sans modèle ne peut pas être le niveau par défaut.
- **Activé** : désactivé, le niveau n’est plus proposé aux utilisateurs. Le niveau par défaut ne peut pas être désactivé.

### Configurer l’environnement d’exécution

L’environnement d’exécution se configure dans **Environnement d'exécution du chat IA**, sous l’onglet **Chat IA**. Une fois le déploiement terminé, cliquez sur **Run test** pour vérifier l’environnement d’exécution du Chat IA.

### Activer les fonctionnalités IA

Dans **Capacités IA**, en haut de la page, activez **Champ IA** et **Chat IA** selon vos besoins. Ces interrupteurs s’appliquent à toute l’instance. Configurez l’environnement d’exécution avant d’utiliser le **Chat IA**.

### Configurer le Générateur d’Applications

Dans l’onglet **Générateur d’applications**, choisissez sous **Vercel Deploy** comment les Applications sont déployées :

| Moteur de déploiement | Exigences de configuration |
|------|------|
| **Vercel** | Saisissez un jeton d’accès Vercel, cliquez sur **Test Connection**, puis utilisez **Tester l’accès public** pour confirmer que Vercel peut atteindre votre instance Teable et votre stockage d’objets. |
| **Infrastructure Teable** | Utilise l’environnement d’exécution de conteneur Infrastructure Teable configuré. Aucune information d’identification supplémentaire ni test d’accès public n’est requis ici. |

Vous pouvez ajouter les paramètres facultatifs suivants du Générateur d’Applications si nécessaire :

| Élément facultatif | Cas d’utilisation |
|------|------|
| **Domaine personnalisé** | Lorsque vous souhaitez publier des Applications sous votre propre domaine |
| **Authentification de l’Application** | Lorsque les Applications générées nécessitent une connexion par **OTP par e-mail**, **Google** ou **SSO (OIDC)** |

Dans **Authentification de l’Application**, vous pouvez configurer des fournisseurs de connexion pour les Applications générées :

- **OTP par e-mail** utilise une boîte aux lettres SMTP indépendante pour les e-mails de vérification de connexion à l’Application.
- **Google OAuth** nécessite un ID client et un secret client. Ajoutez l’URI de redirection affichée sur cette page à la liste des URI de redirection autorisés dans Google Cloud Console.
- **SSO (OIDC)** permet aux visiteurs de l’Application de se connecter via le fournisseur d’identité de votre entreprise. Enregistrez l’URL affichée sur la page comme URI de redirection auprès de votre fournisseur d’identité, puis renseignez **URL d'autorisation**, **URL du jeton**, **URL des informations utilisateur**, **ID client** et **Secret client**. Si **Scope** reste vide, la valeur `openid email profile` est utilisée.

La connexion **Teable** est disponible par défaut. **OTP par e-mail** apparaît dans le Générateur d’Applications uniquement une fois les paramètres SMTP terminés, **Google** apparaît uniquement une fois les deux informations d’identification OAuth configurées, et **SSO (OIDC)** uniquement une fois tous les champs SSO renseignés, à l’exception du scope.

Dans **Paramètres des apps**, **Injecter automatiquement la clé API IA dans les Applications** est activé par défaut, afin que les Applications puissent appeler les modèles IA de la plateforme. Désactivez-le et les Applications ne pourront plus les atteindre.

Si, après une mise à niveau, d’anciennes Applications ne s’affichent plus en aperçu ou ne peuvent plus être publiées, cliquez sur **Lancer la réparation** dans **Compatibilité des anciens projets**, sous **Outils de maintenance**, pour rétablir automatiquement les fichiers manquants.

### Facultatif : configurer la saisie vocale

Pour utiliser la saisie vocale dans le Chat IA, activez **Saisie vocale** dans l’onglet **Chat IA** et saisissez une **Clé API OpenAI**. Configurez le **Point de terminaison de transcription** uniquement si vous utilisez un service de transcription personnalisé. Vous pouvez également limiter la durée d’enregistrement et le nombre de requêtes par minute.

### Vérifier la configuration

Une fois la configuration terminée, vérifiez d’abord que tous les éléments requis du panneau **Configuration en attente** sont verts. Testez ensuite le **Chat IA**, les **Champs IA**, l’**Automatisation IA** et le **Générateur d’Applications** un par un.
