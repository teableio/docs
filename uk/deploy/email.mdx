## Варіант 1. Системне адміністрування (рекомендовано) {#option-1-admin-panel-recommended}

Найпростіше налаштувати електронну пошту через розділ «Системне адміністрування»:

1. Увійдіть як адміністратор (перший зареєстрований користувач)
2. Перейдіть до **Системне адміністрування** → **Налаштування екземпляра**
3. Знайдіть розділ **Налаштування електронної пошти**
4. За потреби налаштуйте **Поштові сповіщення** й **Автоматизація електронної пошти**: натисніть кнопку праворуч у рядку, введіть дані SMTP у вікні й збережіть їх

<img
  src="/images/selfhosted/email/2026-10-21-admin-settings-email-config.png"
  alt="Налаштування пошти в параметрах екземпляра: пошта для сповіщень і для автоматизацій"
  className="docs-screenshot"
/>

<Tip>
У вікні налаштування можна перевірити надсилання: перед збереженням введіть тестову адресу електронної пошти й натисніть **Надіслати**, щоб переконатися, що параметри SMTP працюють.
</Tip>

- **Поштові сповіщення**: використовується для підтвердження користувачів, скидання пароля, запрошень, системних сповіщень та подібних листів. Саме вона робить доступним варіант **Увійти за кодом з листа** на сторінці входу.
- **Автоматизація електронної пошти**: використовується як стандартний поштовий сервіс для дій автоматизації «Надіслати електронного листа». Для окремої дії «Надіслати електронного листа» також можна налаштувати власний [SMTP-сервер](/uk/basic/automation/actions/communication/smtp-sender).

### Джерела налаштувань і пріоритет

Рекомендуємо спочатку налаштувати поштовий сервіс у розділі **Системне адміністрування → Налаштування екземпляра → Налаштування електронної пошти**. Застосовується такий порядок пріоритетності:

1. **Власний поштовий сервер у дії «Надіслати електронного листа»**: застосовується лише до цієї конкретної дії «Надіслати електронного листа» в поточній автоматизації.
2. **Системне адміністрування → Налаштування екземпляра → Налаштування електронної пошти → Автоматизація електронної пошти**: використовується для листів автоматизації, якщо для дії «Надіслати електронного листа» не налаштовано власний поштовий сервер.
3. **Системне адміністрування → Налаштування екземпляра → Налаштування електронної пошти → Поштові сповіщення**: використовується для підтвердження користувачів, скидання пароля, запрошень, системних сповіщень та подібних листів. Також використовується для листів автоматизації як резервний варіант, якщо пошту для автоматизацій не налаштовано.
4. **Змінні середовища `BACKEND_MAIL_*`**: стандартна конфігурація пошти на рівні розгортання. Використовується лише як резервний варіант, якщо відповідну поштову скриньку не налаштовано в розділі «Системне адміністрування».

### Поля налаштувань

| Поле | Опис | Приклад |
|-------|-------------|---------|
| Адреса сервера | Адреса SMTP-сервера | `smtp.gmail.com` |
| Порт | Порт SMTP | `465` (SSL) або `587` (TLS) |
| SSL/TLS | Чи використовувати SSL/TLS | `true` |
| Ім’я користувача | Користувач для автентифікації SMTP | `noreply@company.com` |
| Пароль | Пароль SMTP або пароль застосунку | `xxxxxxxxxxxxxx` |
| Адреса відправника | Адреса в полі «Від» | `noreply@company.com` |
| Ім’я відправника | Відображуване ім’я | `Сповіщення Teable` |

## Варіант 2. Змінні середовища {#option-2-environment-variables}

Якщо у вашому розгортанні зручніше використовувати конфігураційні файли, задайте змінні середовища:

<Note>
Рекомендуємо спочатку налаштувати **Поштові сповіщення** й **Автоматизація електронної пошти** в розділі **Системне адміністрування → Налаштування екземпляра → Налаштування електронної пошти**. Змінні середовища переважно використовуються як стандартні налаштування та резервна конфігурація на рівні розгортання.
</Note>

```sh
BACKEND_MAIL_HOST=smtp.example.com
BACKEND_MAIL_PORT=465
BACKEND_MAIL_SECURE=true
BACKEND_MAIL_SENDER=noreply@company.com
BACKEND_MAIL_SENDER_NAME=Teable
BACKEND_MAIL_AUTH_USER=username
BACKEND_MAIL_AUTH_PASS=your_password
```

<Note>
Після зміни змінних середовища необхідно **перезапустити** контейнер Teable, щоб зміни набули чинності.
</Note>

## Приклади для постачальників SMTP

<Accordion title="AWS SES">
```sh
# Як отримати: консоль AWS → Simple Email Service → Налаштування SMTP → Створити облікові дані SMTP
BACKEND_MAIL_HOST=email-smtp.us-east-1.amazonaws.com  # Замініть на свій регіон
BACKEND_MAIL_PORT=465
BACKEND_MAIL_SECURE=true
BACKEND_MAIL_SENDER=noreply@yourdomain.com  # Має бути підтверджена адреса відправника
BACKEND_MAIL_SENDER_NAME=Сповіщення Teable
BACKEND_MAIL_AUTH_USER=your_smtp_username   # Ім’я користувача AWS SMTP
BACKEND_MAIL_AUTH_PASS=xxxxxxxxxxxxxx       # Пароль AWS SMTP
```
</Accordion>

<Accordion title="Gmail">
```sh
# Як отримати: обліковий запис Google → Безпека → Двоетапна перевірка → Паролі застосунків
BACKEND_MAIL_HOST=smtp.gmail.com
BACKEND_MAIL_PORT=465
BACKEND_MAIL_SECURE=true
BACKEND_MAIL_SENDER=you@gmail.com
BACKEND_MAIL_SENDER_NAME=Сповіщення Teable
BACKEND_MAIL_AUTH_USER=you@gmail.com
BACKEND_MAIL_AUTH_PASS=xxxxxxxxxxxxxx  # 16-значний пароль застосунку
```
</Accordion>

<Accordion title="Microsoft 365 / Outlook">
```sh
# Як отримати: центр адміністрування Microsoft 365 → Безпека → Політики та правила → Автентифікація електронної пошти
BACKEND_MAIL_HOST=smtp.office365.com
BACKEND_MAIL_PORT=587
BACKEND_MAIL_SECURE=true
BACKEND_MAIL_SENDER=your.name@yourdomain.com
BACKEND_MAIL_SENDER_NAME=Сповіщення Teable
BACKEND_MAIL_AUTH_USER=your.name@yourdomain.com
BACKEND_MAIL_AUTH_PASS=xxxxxxxxxxxxxx  # Ваш пароль Microsoft 365 або пароль застосунку
```
</Accordion>

<Accordion title="SendGrid">
```sh
# Як отримати: панель SendGrid → Налаштування → Ключі API → Створити ключ API
BACKEND_MAIL_HOST=smtp.sendgrid.net
BACKEND_MAIL_PORT=465
BACKEND_MAIL_SECURE=true
BACKEND_MAIL_SENDER=noreply@yourdomain.com
BACKEND_MAIL_SENDER_NAME=Сповіщення Teable
BACKEND_MAIL_AUTH_USER=apikey
BACKEND_MAIL_AUTH_PASS=xxxxxxxxxxxxxx  # Ваш ключ API SendGrid
```
</Accordion>
