### 路径

POST /api/table/\{tableId}/record

### 请求

#### 路径参数

* tableId (string): 表的唯一标识符。

#### 请求体

* **records（必填）**
  * 描述：要创建的记录数组
  * 类型：数组
  * 示例：
    ```json
    [
      {
        "fields": {
          "Name": "John Doe",
          "Age": 30,
          "Email": "john@example.com"
        }
      },
      {
        "fields": {
          "Name": "Jane Smith",
          "Age": 28,
          "Email": "jane@example.com"
        }
      }
    ]
    ```
  * 说明：每个记录都是一个包含 `fields` 对象的项。`fields` 对象包含字段名和对应的值，每一种字段值结构都不一样，详情请[查看记录字段值类型](/zh/api-doc/record/interface)。
  * 默认值：未传入 `fields` 的字段会使用表格中配置的默认值。如果必填字段没有默认值，或你显式传入 `null`，请求会失败。
* **fieldKeyType（可选）**
  * 描述：指定字段键的类型
  * 类型：字符串
  * 可选值：
    * "name"：使用字段名作为键
    * "id"：使用字段 ID 作为键
    * "dbFieldName"：使用字段 dbFieldName 作为键
  * 示例：`"name"` 或 `"id"` 或 `"dbFieldName"`
  * 说明：如果不指定，默认使用字段名作为键。
  * 用法：
    * 当设置为 "name" 时：
      ```json
      {
        "fields": {
          "Name": "John Doe",
          "Age": 30
        }
      }
      ```
    * 当设置为 "id" 时：
      ```json
      {
        "fields": {
          "fldABCDEFGHIJKLMN": "John Doe",
          "fldOPQRSTUVWXYZ12": 30
        }
      }
      ```
* **typecast（可选）**
  * 描述：是否自动转换字段值类型，默认会严格校验，需要保证输入的值符合当前字段的数据类型，如果开启则会尝试自动进行转换。
  * 类型：布尔值
  * 可选值：true 或 false
  * 示例：`true`
  * 说明：如果设置为 true，系统会尝试将输入值转换为正确的字段值类型。
  * 用法示例：
    * 关联字段：可以直接使用主键文本进行关联
      ```json
      {
        "User table": "张三"
      }
      ```
    * 日期字段：可以使用非标准格式的日期字符串
      ```json
      {
        "Date": "2023-05-15"
      }
      ```
    * 用户字段：可以直接使用用户名
      ```json
      {
        "Assigned To": "John Doe"
      }
      ```
* **order（可选）**
  * 描述：指定新记录的在指定视图所在的位置
  * 类型：对象
  * 包含以下属性：
    * viewId
      * 描述：视图的 ID [（如何获取）](/zh/api-doc/get-id#视图-id-viewid)
      * 类型：字符串
      * 示例：`"viwABCDEFGHIJKLMN"`
    * anchorId
      * 描述：锚点记录的 ID[（如何获取）](/zh/api-doc/get-id#记录-id-recordid)
      * 类型：字符串
      * 示例：`"rec123456789ABCDE"`
    * position
      * 描述：相对于锚点记录的位置
      * 类型：字符串
      * 可选值：
        * "before"：在锚点记录之前
        * "after"：在锚点记录之后
      * 示例：`"after"`
  * 完整示例：
    ```json
    {
      "viewId": "viwABCDEFGHIJKLMN",
      "anchorId": "rec123456789ABCDE",
      "position": "after"
    }
    ```
  * 说明：使用 order 可以精确控制新记录在特定视图中的位置。

### 响应

#### 成功响应

* 状态码：201 Created
* 响应体：返回创建的记录数据。

**示例响应体**

```json
{
  "records": [
    {
      "id": "record789",
      "fields": {
        "single line text": "text value 1"
      }
    },
    {
      "id": "record567",
      "fields": {
        "single line text": "text value 2"
      }
    }
  ]
}
```

### 错误响应

* 状态码：400 Bad Request: 请求体格式错误或缺少必需字段。
* 状态码：404 Not Found: 指定的表 tableId 不存在。

    },

## 按唯一字段创建或更新记录

同步外部数据时，可以按订单号、客户编号等唯一值匹配记录，无需先查询记录 ID。

```text
POST /api/table/{tableId}/record/upsert
```

<Info>此接口适用于使用 v2 引擎的表，不支持通过分享视图调用。`error` 模式需要创建记录权限；`ignore` 和 `update` 模式同时需要创建、更新记录权限。</Info>

### 请求体

| 参数 | 说明 |
| --- | --- |
| `matchField` | 必填。用于匹配的字段 ID，该字段必须已启用唯一值约束。只支持一个字段，不支持组合键。|
| `onConflict` | 必填。匹配到已有记录时的处理方式，见下表。|
| `records` | 必填。至少包含一条记录，每条记录使用 `fields` 提供字段值，并包含匹配字段的非空值。同一请求中的匹配值不能重复。|
| `fieldKeyType` | 可选。`fields` 中字段键的类型，与创建记录接口一致；`matchField` 始终填写字段 ID。|
| `typecast` | 可选。是否尝试自动转换字段值类型，与创建记录接口一致。|

未匹配到的记录会创建；匹配到已有记录时，按 `onConflict` 处理：

| 值 | 处理方式 |
| --- | --- |
| `error` | 任意匹配值已存在时，整个请求失败。|
| `ignore` | 保留已有记录，跳过该条输入。|
| `update` | 只更新输入中提供的字段，未提供的字段保持原值。|

例如，`fldOrderNumber` 是已启用唯一值约束的订单号字段，以下请求会创建新订单，或更新已有订单的状态：

```json
{
  "fieldKeyType": "id",
  "matchField": "fldOrderNumber",
  "onConflict": "update",
  "records": [
    {
      "fields": {
        "fldOrderNumber": "ORDER-001",
        "fldStatus": "已付款"
      }
    }
  ]
}
```

### 响应

成功响应中的 `results` 与输入记录顺序一致，`index` 从 0 开始；`summary` 汇总请求条数及各类结果数量。

| `status` | 含义 |
| --- | --- |
| `created` | 已创建新记录。|
| `updated` | 已更新已有记录。|
| `unchanged` | 已有记录与提供的值一致，或没有字段需要更新。|
| `skipped` | `ignore` 模式下跳过了已有记录。|

只有调用者有权读取该条记录时，结果才包含 `recordId` 和 `record`；字段内容仍受读取权限限制。

```json
{
  "results": [
    {
      "index": 0,
      "status": "updated",
      "recordId": "recExample",
      "record": {
        "id": "recExample",
        "fields": {
          "fldOrderNumber": "ORDER-001",
          "fldStatus": "已付款"
        }
      }
    }
  ],
  "summary": {
    "requested": 1,
    "created": 0,
    "updated": 1,
    "unchanged": 0,
    "skipped": 0
  }
}
```
