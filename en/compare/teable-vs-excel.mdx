Excel models calculations in cells and workbooks; Teable organizes typed records and relationships that apps and workflows can share. Use this guide to plan the data model and import steps.

## Database vs Spreadsheet: Key Differences Explained

### 1. Data Security and Access Control

Excel files on OneDrive or SharePoint use Microsoft 365 identity and sharing controls. Worksheet protection is different from record-level access. In Teable, configure collaborator roles and the supported table, view, record and field permissions for your plan. Business plan supports role-based permissions for tables, views, records, fields and actions.

[Authority Matrix: roles and data access permissions](/en/basic/authority-matrix)

### 2. Collaborative Data Management

Excel supports real-time coauthoring, version history and Show Changes in supported cloud files. Teable collaborators edit shared records and views. Test who can read, update or delete data with a separate account before inviting the team.

### 3. Handling Large Datasets

Excel supports 1,048,576 rows per worksheet. Teable Cloud limits apply per space and plan. Capacity alone does not predict speed: test formulas, linked data, attachments, filters and concurrent work with a representative sample. Pro: 250K rows/space; Business: 1M rows/space

### 4. Advanced Data Operations

For a customer/order workflow, create Customers and Orders tables. Store each customer once, link each order to its customer and use lookup or rollup fields to display related values. In Excel, lookups and the Data Model serve calculation and analytical relationships; moving data also means redesigning the operational record model.

Excel supports VBA, Office Scripts and Power Automate workflows. Office Scripts with Power Automate requires a qualifying Microsoft 365 business license; include tenant policies, connectors and flow ownership in the design.

[Build automations with triggers and actions](/en/basic/automation)

### 5. Data Integrity and Compliance

Excel provides formulas, PivotTables, Power Query, Power Pivot and VBA. Teable formulas compute record fields; linked records, lookups and rollups connect tables. Rebuild workbook formulas and queries for the target model rather than expecting the original workbook logic to execute after import.

## When to Choose Which Solution

Keep Excel for financial models, specialized calculations, offline files and existing VBA/Power Query work. Use Teable for shared operational records, permissions, forms, apps and handoffs; both can be part of the same workflow.

For self-hosted Teable, choose a deployment with the AI and app runtime services your workflow needs. Self-hosted App Builder requires Business or higher.

## FAQ: Common User Questions

**How can I import data into Teable?**

Upload an Excel file of 5 MB or less in Teable; save larger datasets as CSV. For a new table, choose AI-assisted import or manual field setup. Check field types and column mappings, then rebuild workbook formulas, macros, Power Query, permissions and external connections as needed.

[How can I import data into Teable?](/en/basic/table/import)

**How should I compare the total team cost?**

Compare the total bill for your actual team: paid editors, app users, AI, automation usage, add-ons and hosting. Runs and credits are different billing units. A lower starting seat price does not establish the lower cost for every workflow.
