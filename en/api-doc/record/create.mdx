### Path

POST /api/table/\{tableId\}/record

### Request

#### Path Parameters

* tableId (string): The unique identifier of the table.

#### Request Body

* **records (required)**
  * Description: Array of records to create
  * Type: Array
  * Example:
    ```json
    [
      {
        "fields": {
          "Name": "John Doe",
          "Age": 30,
          "Email": "john@example.com"
        }
      },
      {
        "fields": {
          "Name": "Jane Smith",
          "Age": 28,
          "Email": "jane@example.com"
        }
      }
    ]
    ```
  * Note: Each record is an item containing a `fields` object. The `fields` object contains field names and their corresponding values. Each field type has a different value structure, see [Record Field Value Types](/en/api-doc/record/interface) for details.
  * Default values: Fields omitted from `fields` use the table's default value when one is configured. If a required field has no default value, or if you explicitly pass `null` to a required field, the request fails.
* **fieldKeyType (optional)**
  * Description: Specifies the type of field key
  * Type: String
  * Possible values:
    * "name": Use field name as key
    * "id": Use field ID as key
    * "dbFieldName": Use field dbFieldName as key
  * Example: `"name"` or `"id"` or `"dbFieldName"`
  * Note: If not specified, field name is used as key by default.
  * Usage:
    * When set to "name":
      ```json
      {
        "fields": {
          "Name": "John Doe",
          "Age": 30
        }
      }
      ```
    * When set to "id":
      ```json
      {
        "fields": {
          "fldABCDEFGHIJKLMN": "John Doe",
          "fldOPQRSTUVWXYZ12": 30
        }
      }
      ```
* **typecast (optional)**
  * Description: Whether to automatically convert field value types. By default, strict validation is enforced, requiring input values to match the current field's data type. If enabled, the system will attempt automatic conversion.
  * Type: Boolean
  * Possible values: true or false
  * Example: `true`
  * Note: If set to true, the system will attempt to convert input values to the correct field value type.
  * Usage examples:
    * Link field: Can directly use primary key text for linking
      ```json
      {
        "User table": "John Smith"
      }
      ```
    * Date field: Can use non-standard format date strings
      ```json
      {
        "Date": "2023-05-15"
      }
      ```
    * User field: Can directly use username
      ```json
      {
        "Assigned To": "John Doe"
      }
      ```
* **order (optional)**
  * Description: Specifies the position of new records in a specific view
  * Type: Object
  * Properties:
    * viewId
      * Description: View ID [(how to get)](/en/api-doc/get-id#viewid)
      * Type: String
      * Example: `"viwABCDEFGHIJKLMN"`
    * anchorId
      * Description: Anchor record ID [(how to get)](/en/api-doc/get-id#recordid)
      * Type: String
      * Example: `"rec123456789ABCDE"`
    * position
      * Description: Position relative to the anchor record
      * Type: String
      * Possible values:
        * "before": Before the anchor record
        * "after": After the anchor record
      * Example: `"after"`
  * Complete example:
    ```json
    {
      "viewId": "viwABCDEFGHIJKLMN",
      "anchorId": "rec123456789ABCDE",
      "position": "after"
    }
    ```
  * Note: Using order allows precise control of new record positions in a specific view.

### Response

#### Success Response

* Status code: 201 Created
* Response body: Returns the created record data.

**Example Response Body**

```json
{
  "records": [
    {
      "id": "record789",
      "fields": {
        "single line text": "text value 1"
      }
    },
    {
      "id": "record567",
      "fields": {
        "single line text": "text value 2"
      }
    }
  ]
}
```

### Error Responses

* Status code: 400 Bad Request: Request body format error or missing required fields.
* Status code: 404 Not Found: Specified tableId does not exist.

## Create or update records by a unique field {#upsert-by-unique-field}

When syncing external data, match records by a unique value such as an order number or customer ID without first looking up record IDs.

```text
POST /api/table/{tableId}/record/upsert
```

<Info>This endpoint requires a table using the v2 engine and is unavailable through shared views. The `error` mode requires permission to create records; `ignore` and `update` require permission to both create and update records.</Info>

### Request body

| Parameter | Description |
| --- | --- |
| `matchField` | Required. The ID of the matching field, which must have a unique constraint enabled. Only one field is supported; composite keys are not supported. |
| `onConflict` | Required. How to handle an existing match; see the table below. |
| `records` | Required. At least one record. Each record supplies values in `fields` and must include a non-empty matching value. Matching values cannot repeat within the request. |
| `fieldKeyType` | Optional. The key type used in `fields`, as in the create-records endpoint. Always use a field ID for `matchField`. |
| `typecast` | Optional. Whether to attempt to convert field value types, as in the create-records endpoint. |

Records without a match are created. Existing matches are handled according to `onConflict`:

| Value | Behavior |
| --- | --- |
| `error` | The entire request fails if any matching value already exists. |
| `ignore` | Keep the existing record and skip that input record. |
| `update` | Update only the supplied fields; omitted fields retain their values. |

For example, if `fldOrderNumber` is an order-number field with a unique constraint, this request creates a new order or updates the status of an existing order:

```json
{
  "fieldKeyType": "id",
  "matchField": "fldOrderNumber",
  "onConflict": "update",
  "records": [
    {
      "fields": {
        "fldOrderNumber": "ORDER-001",
        "fldStatus": "Paid"
      }
    }
  ]
}
```

### Response

In a successful response, `results` follows the input order and `index` starts at 0. The `summary` object counts requested records and each outcome.

| `status` | Meaning |
| --- | --- |
| `created` | A new record was created. |
| `updated` | An existing record was updated. |
| `unchanged` | The existing values already match, or there are no fields to update. |
| `skipped` | An existing record was skipped in `ignore` mode. |

Results include `recordId` and `record` only when the caller can read that record. Field contents remain subject to read permissions.

```json
{
  "results": [
    {
      "index": 0,
      "status": "updated",
      "recordId": "recExample",
      "record": {
        "id": "recExample",
        "fields": {
          "fldOrderNumber": "ORDER-001",
          "fldStatus": "Paid"
        }
      }
    }
  ],
  "summary": {
    "requested": 1,
    "created": 0,
    "updated": 1,
    "unchanged": 0,
    "skipped": 0
  }
}
```
